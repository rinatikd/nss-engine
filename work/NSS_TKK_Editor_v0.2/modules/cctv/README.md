# СВН для AutoCAD 2026 (v0.1, ядро без плагина)
1. В AutoCAD: SAVEAS → DXF (R2000/R2010 ASCII) → plan.dxf.
2. Заполнить cameras.csv (x,y — в единицах чертежа, мм; rotation — от оси X против часовой).
3. python3 cctv_cli.py plan.dxf cameras.csv result.dxf --layers <слои стен> --days 30 --xlsx spec.xlsx
4. В AutoCAD: открыть result.dxf (или XREF/INSERT) — слои CCTV_CAM, CCTV_FOV, CCTV_DORI, CCTV_TEXT, WALLS_REF.
Ограничения v0.1: 2D, стены только LINE/POLYLINE/LWPOLYLINE (блоки и ARC не читаются), ASCII DXF,
нормы РК не проверяются (ждём тексты СТ РК 4031-2026 и правил видеомониторинга), результат в реальном AutoCAD не проверялся.
Тесты: python3 test_cctv_core.py

Проверки входа: CLI отклоняет пустую ведомость камер, нечисловые/нефинитные параметры,
неположительный масштаб/срок архива, неизвестный уровень DORI и фокус вне диапазона модели
(также при `python -O`). Выходные DXF/XLSX должны отличаться друг от друга и от входных файлов.
Ошибки этих проверок не заменяют существующий DXF. DXF сохраняется атомарно; XLSX и DXF
не составляют единую транзакцию. Кириллица в выходном R12 DXF записывается через DXF Unicode escapes;
размер и отступ подписей учитывают `--unit`.

Независимая проверка структуры/геометрии результата через `ezdxf` включается в `test_cctv_core.py`,
если пакет установлен; без него этот тест пропускается. Это проверка синтетического DXF,
не приёмка в AutoCAD. Криволинейные сегменты (bulge), 3D/OCS, блоки и кодировки старых
входных DXF требуют отдельной предметной проверки. Текущий расчёт остаётся плоским,
с прямыми отрезками и дискретными лучами; высота/наклон не моделируют 3D-окклюзию.
