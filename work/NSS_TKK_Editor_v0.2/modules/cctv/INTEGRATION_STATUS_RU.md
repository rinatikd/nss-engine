# Модуль СВН в NSS_Engine

Исходный модуль из `cctv_project.zip` размещён отдельно от редактора телефонной канализации в `modules/cctv`. Команда AutoCAD `NSS_CCTV_ANALYZE` принимает подготовленный DXF препятствий и CSV размещения камер, запускает `cctv_cli.py` через упакованный Python и пишет новый `*_CCTV_result.dxf`; активный чертёж не меняется.

Ядро читает текстовый UTF-8 DXF (включая проверенный AC1032-план), но извлекает препятствия только из LINE/LWPOLYLINE/POLYLINE в ENTITIES. ARC, вложенные блоки/XREF и высоты препятствий не учитываются. Для дверей с символами открывания сначала требуется нормализовать препятствия в закрытое положение. Полноценного чтения слоёв из активного DWG пока нет.

CLI берёт HFOV и DORI-дальности из `catalog.csv` по паспортам камеры; при отсутствии паспортных значений используются расчётные DORI-пороги по пикселям. Это закреплено end-to-end тестом. Тесты `test_cctv_core.py` проходят (9), .NET-плагин собирается без предупреждений, а упаковщик включает каталог и тестирует модуль после распаковки.

Первый этаж проверен на планах заказчика: 20 камерных подписей и 20 треугольников-направлений сопоставлены без пропусков и лишних символов; нормализовано 7 859 отрезков препятствий. Результаты находятся в `evidence/cctv_sadik_first_floor_run/`. Все длины/высоты остаются 2D-допущениями проекта; монтажные высоты большинства камер требуют подтверждения. Архив 5,599 ТБ рассчитан для этих 20 камер на 30 суток при 0,72 Мбит/с и запасе 20%; это не итог по всему объекту. Сводка по прогону — `evidence/cctv_sadik_first_floor_run/СВН_первый_этаж_расчёт_RU.md`.

Остальные сценарии (помещения, второй этаж, подвал, территория), проверка нормативов Казахстана и пользовательский GUI для выбора слоёв/параметров остаются незавершёнными. Проектные файлы второго этажа, высоты и нормативный текст СТ РК 4031-2026 для этих задач отсутствуют.
