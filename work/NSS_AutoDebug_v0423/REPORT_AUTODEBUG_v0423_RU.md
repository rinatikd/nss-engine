# NSS AutoDebug v0.42.3 — 20.10.2026

Исправлен загрузчик автоматической проверки после фактической ошибки v0.42.2: `Assembly with same name is already loaded`. Последующая `no function definition` означала, что новая тестовая функция не зарегистрировалась; результаты native-тестов отсутствуют.

## Изменения

При сборке каждый запуск получает собственные имена сборки, команды и LispFunction, связанные с UUID. Отладочная сборка не регистрирует рабочие команды старого плагина. Общие реализации экспортёра, preview и Python-моста сохранены. Комплектная DLL без SDK имеет отдельное имя NssEngine.AutoDebug.V0423 и версию 0.42.3.0.

Загрузчик проверяет наличие именно своей функции до и после NETLOAD. При ошибке создаётся bootstrap_error.json с UUID и подробностями, сборщик завершает ожидание с BOOTSTRAP_FAILED. Вызова отсутствующей функции больше нет. Повторный вызов завершённого native-прогона не повторяет тестовые изменения.

Preview-тесты меняют только отдельную disposable Database. Открывается созданный синтетический fixture_copy.dxf; исходный DWG не изменяется. Проверяются UUID, путь и SHA-256 входа/DLL. Профиль, реестр и SECURELOAD не меняются.

## Фактические проверки

Два независимых запуска `--prepare --in-host` завершились PREPARED. В каждом прошли 265 Python-тестов, 18 C# contract-проверок и сборка DLL. Проверка метаданных скомпилированных сборок обнаружила ровно две регистрации: уникальную команду и уникальную LispFunction. Имена двух сборок и функций различаются. Логи и JSON сохранены в Evidence.

Выполнена сборка комплектной DLL через .NET SDK и установленные reference DLL AutoCAD 2026: 0 предупреждений, 0 ошибок. Выполнена подготовка `--prepare --use-prebuilt` с проверкой SHA-256. До исправления условной регистрации старых команд один промежуточный прогон выявил нарушение проверки совместимости; после исправления полные тесты прошли в обоих финальных запусках.

Команды из каталога комплекта:

```text
runtime/python.exe -E -s -X utf8 scripts/autodebug_v0421.py --prepare --in-host
dotnet build autocad/NssEngine.Export.csproj -c Release -o Deploy "-p:AutoCADDir=C:\Program Files\Autodesk\AutoCAD 2026" -p:NuGetAudit=false --nologo
runtime/python.exe -E -s -X utf8 scripts/autodebug_v0421.py --prepare --use-prebuilt
```

Подготовка сама запускает unittest discover, C# contract harness и проверку метаданных. Полные аргументы сборок и результаты находятся в Evidence/*/dotnet-build.log, python-tests.log, contract-tests.log, assembly_registration.json. ZIP проверяется CRC и манифестом SHA-256, затем проверяется подготовка из распакованного комплекта.

## Что осталось непроверенным

Загрузка v0.42.3 и 14 native-проверок внутри AutoCAD ещё не выполнены. PREPARED не означает успешную работу плагина. Исправленный LISP проверен генерацией и тестами, но не исполнением AutoLISP. Уникальность метаданных не заменяет проверку загрузки в процессе AutoCAD.

Предыдущий автоматический запуск AutoCAD из среды инструмента завершался до native-отчёта с ошибкой TEMP; поэтому для следующего прогона выбран обычный открытый AutoCAD и START_IN_AUTOCAD.cmd. Предыдущие подтверждения экспорта v0.42 не считаются подтверждением этой DLL. Геометрический анализ четырёх реальных DXF в данном исправлении загрузчика повторно не запускался. Сетевой NuGet audit отключён; аудит зависимостей не заявляется.

Следующий этап: получить native_results.json и Python status/analysis, устранить обнаруженные native-ошибки, затем провести такой же пакетный прогон на копиях реальных проектов. До этого v0.43 с новыми проектными возможностями не объявляется готовой.
