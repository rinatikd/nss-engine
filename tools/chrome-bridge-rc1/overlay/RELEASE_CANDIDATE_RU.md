# Chrome Bridge 0.2.1-rc.2 — кандидат для локальной приёмки

Дата: 30.10.2026. Канонический source-only кандидат собирается builder из 74
файлов; runtime — `0.2.1-rc.2`, стандартный порт — `17381`. Изолированный
Windows-пакет на `17384` — отдельный вариант развёртывания, а не новый
канонический исходник. Рабочий RC1 на `17383` и его состояние сохраняются.

## Что проверено

- CI [40937637445](https://github.com/rinatikd/nss-engine/actions/runs/40937637445)
  прошёл на Windows/Linux с Node.js 22/24, включая синтетический MV3 smoke.
  Синтетический браузерный тест не подтверждает работу живых сайтов.
- На RC1 подтверждался обмен Codex CLI → MCP → веб-интерфейс Claude.
  Этот результат не переносится автоматически на RC2.
- Новые локальные логи RC2 показывают `connected=true`, `pendingQueue=0`,
  `activeGrantCount=3`, `siteCount=7`, `claudePermission=true`. Одновременно
  `claudeTabs=0`, `agentBindingCount=0`, `actions=false`.
  Соединение и разрешение сайта наблюдались; привязка Claude и отправка/ответ
  на RC2 пока не подтверждены. Финальная live-приёмка остаётся открытой.

RC2 включает строгий JSON-RPC для HTTP/stdio, резервирование вкладки перед
отправкой, проверку живого разрешения перед изменением чата, отзыв незавершённых
разрешений через Stop и локальную диагностику без вывода приватного config.
`CODEX_DISABLED` сохранён: подключение Codex как MCP-клиента не включает
встроенный запуск Codex. Бюджет платных API — 0; платные API не вызываются.

## Windows: стандартный запуск и изолированный RC2

Нужен Node.js >=22; для обычного запуска `npm install` не требуется. Распакуйте
кандидат в отдельный каталог и выполняйте команды из его корня. Для проверки
используйте отдельный профиль Chrome. Существующий RC1 не останавливайте,
не перезаписывайте его файлы, config, разрешения и MCP-регистрацию.

Перед запуском сверьте распакованные файлы с `SHA256SUMS.txt`: builder включает
74 исходных файла и `CANDIDATE_READY.json` (75 записей), сам список исключён.
Например, `Get-FileHash .\CANDIDATE_READY.json -Algorithm SHA256` должен совпасть
с соответствующей строкой списка; так же сверяются остальные файлы. Контрольные
суммы подтверждают соответствие пакету, а не завершение live-приёмки.

| Вариант | Порт сервера и клиента | Отдельный каталог состояния |
| --- | --- | --- |
| Стандартный source-only RC2 | `17381` | `ChromeBridge-RC2-17381` |
| Изолированный Windows RC2 рядом с RC1 | `17384` | `ChromeBridge-RC2-17384` |
| Уже работающий RC1 | `17383` | Существующий каталог RC1, без изменений |

У стандартного расширения endpoint в `extension/control.js` и loopback
`host_permissions` в `extension/manifest.json` рассчитаны на `17381`.
Для варианта `17384` используйте отдельный пакет, где оба значения подготовлены
для `17384`. Endpoint расширения, разрешение manifest, сервер и MCP-клиент
должны указывать на один порт. Одной переменной окружения для смены порта
расширения недостаточно. Если порт занят, не завершайте чужой процесс.

1. В отдельном профиле откройте `chrome://extensions`, включите режим
   разработчика и загрузите папку `extension` выбранного RC2 как распакованную.
   Скопируйте фактический новый ID (32 буквы a–p); ID и токен RC1 не используйте.
2. В PowerShell задайте состояние и порт. Пример для изолированного пакета:

   ```powershell
   $env:CHROME_BRIDGE_HOME = Join-Path $env:LOCALAPPDATA 'ChromeBridge-RC2-17384'
   $env:CHROME_BRIDGE_PORT = '17384'
   .\Setup-Windows.ps1 -ExtensionId <НОВЫЙ_ID_RC2> -CopyBrowserToken
   .\Start-Bridge.ps1
   ```

   Для стандартного варианта замените каталог на `ChromeBridge-RC2-17381`,
   порт на `17381`. Setup не печатает токены. Вставьте browserToken из буфера
   только в локальное окно управления соответствующего расширения RC2,
   очистите буфер и его историю, нажмите Connect. Не передавайте токены в чат,
   отчёт, командную строку или репозиторий. Окно сервера держите открытым.
3. В каждом следующем PowerShell задавайте **обе** переменные с теми же
   значениями, прежде чем запускать doctor, проверку или регистрацию клиента:

   ```powershell
   $env:CHROME_BRIDGE_HOME = Join-Path $env:LOCALAPPDATA 'ChromeBridge-RC2-17384'
   $env:CHROME_BRIDGE_PORT = '17384'
   .\Doctor-Bridge.ps1 -Live
   .\Connect-Agents.ps1
   ```

   `Connect-Agents.ps1` без `-Apply` показывает конфигурацию и ничего не меняет.
   Для стандартной установки без существующей регистрации можно выполнить
   `.\Connect-Agents.ps1 -Target Codex -Apply` или `-Target Claude -Apply`.
   Помощник использует имя `chrome-bridge` и отказывается заменять его.

   Рядом с RC1 зарегистрируйте RC2 под отдельным свободным именем, сохраняя
   обе переменные в определении MCP. Выполните команду нужного клиента:

   ```powershell
   $nodePath = (Get-Command node -CommandType Application).Source
   $stdioPath = Join-Path (Get-Location).Path 'server\stdio.mjs'
   codex mcp add chrome-bridge-rc2 --env "CHROME_BRIDGE_HOME=$env:CHROME_BRIDGE_HOME" --env "CHROME_BRIDGE_PORT=$env:CHROME_BRIDGE_PORT" -- $nodePath $stdioPath
   claude mcp add chrome-bridge-rc2 --transport stdio --scope user --env "CHROME_BRIDGE_HOME=$env:CHROME_BRIDGE_HOME" --env "CHROME_BRIDGE_PORT=$env:CHROME_BRIDGE_PORT" -- $nodePath $stdioPath
   ```

   Не заменяйте уже существующее имя. Откройте новую сессию клиента и выбирайте
   инструменты именно RC2. Откат только этой регистрации:
   `codex mcp remove chrome-bridge-rc2` либо
   `claude mcp remove --scope user chrome-bridge-rc2`.
4. В расширении RC2 локально добавьте нужный сайт, например `https://claude.ai`,
   в режиме чата и откройте существующую беседу. Разрешение сайта само по себе
   не создаёт вкладку или привязку. Через MCP RC2 выполните `agent_list`, затем
   `agent_bind` к обнаруженной вкладке. Нажать **Grant control** может только
   человек локально в Chrome; автоматизировать выдачу browser grant нельзя.
   Проверьте привязку и доступные действия через `agent_selftest`.
5. Сначала выполните проверку без отправки:

   ```powershell
   .\Verify-Live.ps1
   .\Verify-Live.ps1 -Agent claude
   ```

   Когда вкладка найдена, агент привязан и локальный grant действует, отдельный
   тест одной отправки запускается так:

   ```powershell
   .\Verify-Live.ps1 -Agent claude -SendTest -Report .\acceptance-rc2-claude.json
   ```

   Укажите фактическое имя привязанного агента. Скрипт отправляет один запрос
   с кодом и не повторяет отправку при неопределённом результате. После ошибки
   осмотрите чат; каждый новый запуск `-SendTest` создаёт новый запрос.

## Как принять результат

`passed` относится только к запрошенным проверкам. Проверка по умолчанию
показывает доступность MCP и состояние Chrome. `functionalAgentObserved`
означает наблюдение ответа с кодом в тесте, но не доказывает его атрибуцию:
`deliveryStatus=UNKNOWN`, `replyAttribution=UNVERIFIED`.

Для окончательной приёмки RC2 нужны фактические Windows setup/start и отдельная
MCP-регистрация, найденная и привязанная вкладка, отправка и ответ для каждого
заявленного провайдера, Stop/отзыв разрешения и повтор `requestId` в настоящем
расширении. Подключение ChatGPT app и изоляция встроенного выполнения Codex,
если их заявляют, требуют отдельных проверок. Текущие логи этих результатов
не подтверждают; прямая автоматическая передача между аккаунтами ChatGPT
этим кандидатом не реализована.
