# Chrome Bridge 0.2.1-rc.2 — кандидат для локальной приёмки

Дата: 28.10.2026. Основа — Chrome-Bridge-Handoff-20261028-RELEASE.zip,
SHA256 b1dc2efc8479be8e6e7af18b9b05f36f7e0d38ed2fc9f5b1829c1fbfe3d208f3.
Этот кандидат не подтверждает подключение ChatGPT или работу живых сайтов.

## Исправлено

- MCP stdio: ошибки разбора, уведомления, переносы строк, проверка ID ответа,
  ограниченное ожидание, запрет редиректов, завершение без потери stdout.
- Одинаковая проверка JSON-RPC в HTTP и stdio; строгая диагностика каталога.
- Отправка резервирует вкладку до первого асинхронного запроса. Параллельные
  отправки, псевдонимы вкладки и перепривязка не должны обходить резервирование.
- Перед редактированием и отправкой расширение проверяет живое разрешение
  конкретной команды. Stop отзывает незавершённые разрешения.
- Повреждённый приватный config не попадает в сообщения об ошибках.
- Настройка ID расширения, диагностика и явная регистрация клиентов.
- Локальная приёмка с обезличенным отчётом и отдельным тестом отправки.

## Запуск на Windows

Используйте отдельную копию кандидата и отдельный профиль Chrome для первой
проверки. Не подменяйте работающий production до локальной приёмки.
Нужен Node.js >=22; для обычного моста npm install не требуется.

1. В chrome://extensions включите режим разработчика, загрузите папку extension
   как распакованное расширение и скопируйте его ID (32 буквы a–p).
2. В PowerShell из корня кандидата задайте отдельный каталог состояния:

   $env:CHROME_BRIDGE_HOME = Join-Path $env:LOCALAPPDATA 'ChromeBridge-RC1'
   .\Setup-Windows.ps1 -ExtensionId <ID> -CopyBrowserToken
   .\Start-Bridge.ps1

   Setup не печатает токены. Вставьте browserToken из буфера только в окно
   управления расширения, очистите буфер и нажмите Connect. Окно моста держите
   открытым. Этот каталог состояния нужно использовать во всех следующих окнах.
3. Во втором PowerShell задайте тот же CHROME_BRIDGE_HOME и выполните:

   .\Doctor-Bridge.ps1 -Live
   .\Connect-Agents.ps1

   Последняя команда — предварительный просмотр без изменения конфигурации.
   Для регистрации: .\Connect-Agents.ps1 -Target Codex -Apply
   или -Target Claude -Apply. Существующую регистрацию помощник не заменяет.
   После регистрации откройте новую сессию клиента. Удаление: codex mcp remove
   chrome-bridge либо claude mcp remove --scope user chrome-bridge.
4. В расширении добавьте https://claude.ai, https://gemini.google.com либо
   https://chat.deepseek.com в режиме чата. Откройте существующую беседу,
   выполните agent_list и agent_bind через клиент. Разрешение управления
   выдавайте локальной кнопкой Grant control. Самотест: agent_selftest.
5. Приёмка без отправки:

   .\Verify-Live.ps1
   .\Verify-Live.ps1 -Agent claude

   Явный один тест отправки в привязанный чат:

   .\Verify-Live.ps1 -Agent claude -SendTest -Report .\acceptance-claude.json

   Используйте фактическое имя привязанного агента. Скрипт отправит один запрос
   с кодом и не станет повторять отправку при неопределённом результате.
   После ошибки сначала осмотрите чат. Каждый повторный запуск с SendTest —
   новый явный запрос, а не продолжение прежнего.

Порт расширения по умолчанию фиксирован: 17381. Если он занят, не останавливайте
чужой процесс: используйте отдельную машину либо согласованно настройте копию
extension/control.js и host_permissions в extension/manifest.json на другой
loopback-порт, задав тот же CHROME_BRIDGE_PORT серверу и клиенту. Одной переменной
сервера для смены порта недостаточно.

## Что означает результат

passed в Verify-Live относится только к запрошенным проверкам. По умолчанию
это доступность MCP и состояния подключённого Chrome. functionalAgentObserved
показывает наблюдение ответа с кодом в явно запрошенном тесте; это не доказанная
атрибуция ответа. deliveryStatus остаётся UNKNOWN, replyAttribution — UNVERIFIED.
Имитированные тесты не считаются проверкой настоящего Chrome или сайта.

## Условия окончательной приёмки

- Windows setup/start/registration реально выполнены и обратимы.
- MCP подключён в настоящем клиенте, Chrome виден, сайты доступны по разрешению.
- Для каждого заявленного провайдера реально проверены отправка и ответ.
- Stop/отзыв разрешений и повтор requestId проверены в настоящем расширении.
- Если заявлен ChatGPT app — отдельно проверено его внешнее подключение.
- Если заявлено выполнение Codex через Bridge — отдельно проверена изоляция.

В этой облачной среде Windows отсутствует, а политика Chromium запрещает загрузку
распакованных расширений. Эти этапы не пройдены. CODEX_DISABLED сохранён. Реальные
платные API не вызывались. Прямая автоматическая передача между аккаунтами ChatGPT
этим кандидатом не реализована.
