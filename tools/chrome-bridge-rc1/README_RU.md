# Chrome Bridge — локальная приёмка 0.2.1-rc.2

Здесь есть автономная сборка из исходников и отдельное текстовое обновление к переданному владельцем архиву
`Chrome-Bridge-Handoff-20261028-RELEASE.zip`.
SHA256 исходного ZIP:
`b1dc2efc8479be8e6e7af18b9b05f36f7e0d38ed2fc9f5b1829c1fbfe3d208f3`.
Сам ZIP, рабочие настройки, учётные данные и чертежи в GitHub не включены.
Основа ветки: main `ac6eb04`. Production и main не менялись.

## Сборка прямо из GitHub — без старого ZIP

Из корня полученной ветки, Node.js >=22:

```powershell
node tools/chrome-bridge-rc1/build-source-candidate.mjs --output "C:\путь\новый-кандидат-rc2"
```

Сборщик проверит 39 исходных файлов и 37 обновлённых файлов по SHA256 и создаст
74 исходных файла, `CANDIDATE_READY.json` и `SHA256SUMS.txt` в новой отдельной папке.
Манифест содержит 75 хешей (все исходники и metadata, исключая сам манифест).
Включены сервер, расширение, Hub, шаблоны,
тесты и инструкции. Исторические отчёты, production-снимки, данные аккаунтов,
старые native-раннеры и бинарники в эту сборку не входят. Нужные для тестов
модули IPC включены как исходники; выполнение Codex остаётся закрытым.

Из новой папки выполните `node --test tests/*.test.mjs`, затем следуйте
`RELEASE_CANDIDATE_RU.md`. Пакет помечен SOURCE_ONLY_CANDIDATE; контрольные суммы
не заменяют приёмку в настоящем браузере. Старый ZIP нужен только для
необязательного полного обновления по инструкции ниже.

## Что изменилось в RC2

Автономные проверки выявили воспроизводимые ошибки в обработке закрытого stdout,
проверке JSON-RPC, атомарной записи настроек/отчётов, ожидании нового запроса,
псевдонимах вкладок и проверках разрешений после асинхронного ожидания.
Исправления покрыты 43 новыми тестами. Рабочая установка оператора RC1
не обновлялась автоматически; подтверждённый live-обмен относится к RC1.
Последний переданный оператором лог RC2 показывает подключение расширения,
но не функциональный диалог: вкладок Claude и привязанных агентов нет.

## Что уже проверено

- Полный набор кандидата: 232 тестов, 218 PASS, 0 FAIL, 14 SKIP.
- Эти же результаты воспроизведены после установки обновления в новую копию.
- Проверка синтаксиса 332 JS/MJS-файлов: ошибок нет.
- Полный установщик: 18 случаев; на Linux 14 PASS и 4 Windows-only SKIP.
  Автономный сборщик: 23 случая; на Linux 21 PASS и 2 Windows-only SKIP.
  Оба проверяют повреждение, обход путей, ссылки и сохранность исходников.
  Полный установщик проверяет 870 исходных файлов до записи.
- 37 изменённых/новых файлов проверяются по SHA256. Автономный исходный кандидат
  содержит 74 исходника и 2 сгенерированных файла; полный необязательный
  установщик исторического ZIP даёт другой, расширенный состав.
- Отдельный помощник воспроизвёл гонку перепривязки и проверил исправление.

Локальные числа относятся к Linux, Node 24.19.0. GitHub CI на коммите `3d8c7a1`
отдельно прошёл Windows/Linux с Node 22/24, изолированные Windows wrapper smoke
и синтетический MV3 E2E. Эти проверки не подтверждают живые сайты и профиль
Chrome владельца. Локальный Chromium этой облачной среды не загрузил расширение;
это не отменяет отдельный успешный браузерный прогон GitHub CI.

## Передача локальному Codex CLI

Скопируйте ему следующий текст:

> Доведи Chrome Bridge до локальной приёмки. Получи ветку
> agent/codex/chrome-bridge-rc1 репозитория https://github.com/rinatikd/nss-engine
> в отдельный clone/worktree, не переключая мою рабочую ветку. Прочитай AGENTS.md
> и tools/chrome-bridge-rc1/README_RU.md. Собери автономный кандидат командой
> node tools/chrome-bridge-rc1/build-source-candidate.mjs --output <новая-папка>.
> Старый ZIP не нужен. Не подменяй работающий Bridge. Запусти тесты кандидата.
> Затем следуй
> RELEASE_CANDIDATE_RU.md в кандидате: настрой ID расширения, проверь MCP и Chrome,
> регистрацию клиента и реальные поддерживаемые сайты. Используй доступные
> инструменты ПК; не утверждай, что Chrome подключён без проверки. Для реальной
> тестовой отправки используй Verify-Live.ps1 -Agent <имя> -SendTest ровно один раз
> на выбранную беседу после локального разрешения управления. Не повторяй
> неопределённую отправку. Не запускай платные API, не снимай CODEX_DISABLED,
> не публикуй config.json и не меняй production без проверенного отката.
> Если нужен ручной шаг в Chrome, сообщи один конкретный шаг вместо долгой
> переписки. Сохрани обезличенный отчёт и продолжай доступную отладку.

## Применение обновления

Из корня полученного репозитория, Node.js >=22:

```powershell
node tools/chrome-bridge-rc1/apply-update.mjs --source "C:\путь\распакованный-архив\chrome-bridge" --output "C:\путь\новый-кандидат-rc2"
```

Исходная папка не меняется. Если хоть один из исходных файлов отличается,
установщик останавливается до создания результата. В этом случае возьмите
свежую распаковку исходного ZIP; не удаляйте собственные изменения. Неописанные
локальные файлы, включая приватные настройки, не копируются. Вывод должен быть
новой папкой вне исходников и пакета обновления. Не выполняйте установку из
каталогов, перенаправленных символическими ссылками/junction.

Из папки кандидата:

```powershell
node --test tests/*.test.mjs
```

Затем откройте `RELEASE_CANDIDATE_RU.md`. Регистрация MCP предварительно
просматривается; применение выбирается явно. Уже существующую регистрацию
помощник не заменяет. Если обновляется действующая установка, отдельно
сохраните регистрацию и настройте откат, прежде чем переключать её.

## Что остаётся до финала

Проверка нового Windows handoff, исправление E2E для разных портов и точный
состав 14 пропущенных тестов описаны в
[отчёте от 30.10.2026](../../docs/CHROME_BRIDGE_RC2_HANDOFF_REVIEW_20261030.md).
Шесть пропусков — пустые заготовки, требующие реализации проверок; одного
добавления Windows-артефактов недостаточно. Приёмка браузерного Bridge
отделена от всё ещё отключённого исполнения Codex через Bridge.

Настоящая Windows-проверка, загрузка расширения, проверка Stop/revoke/replay,
реальный обмен с каждым заявленным сайтом. Для ChatGPT app нужна отдельная
проверка внешнего подключения; stdio-регистрация Codex его не создаёт. Для
запуска Codex через Bridge требуется подтверждённая изоляция, пока он выключен.
Эта версия — кандидат, а не подтверждённый production-релиз.
