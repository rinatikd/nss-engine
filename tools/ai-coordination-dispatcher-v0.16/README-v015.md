# AI Coordination Dispatcher v0.15

Рабочее локальное ядро координации агентов, основанное на загруженной v0.14.
Статус: **145 локальных тестов PASS; реальная модель/публикация/развёртывание не проверены**.
Это не завершённая подключённая A2A-система и не реализация стандартного A2A wire protocol.

**Указание пользователя: платные API недопустимы; бюджет 0.** В новом orchestrator
`PAID_API_ALLOWED=False`, без переключателя CLI или переменной среды для обхода.
Даже при наличии ключа `ClaudeAgent` откажется отправлять запрос. Настоящий канал
ниже описан только как технический задел на случай отдельного будущего решения.
Ключи и требования платных сервисов в конфигурацию среды не добавлялись.

## Что работает

Новый `orchestrator.py` автоматически выполняет цикл:

`QUEUED → EXECUTING → AWAITING_REVIEW → REVIEWING → COMPLETED`

Рецензент может вернуть `REVISE`: исходное задание, рубрика, предыдущий ответ и замечания
автоматически передаются исполнителю. Максимум две итерации исправлений; затем
`REVISION_LIMIT`. `REJECT` завершает задачу как `REJECTED`.

- SQLite WAL: очередь, ответы, отдельные попытки и журнал переходов сохраняются.
- Один шаг резервируется атомарно; два workers не отправят его одновременно.
- Повторный task-id с теми же входами идемпотентен; изменение входов даёт `CONFLICT`.
- После перезапуска сохранённый ответ передаётся рецензенту, исполнитель не вызывается заново.
- Истёкшая lease или неоднозначный ответ провайдера → `UNKNOWN`, без повторной отправки.
- Запоздалый ответ не перезаписывает отмену или восстановление после сбоя.
- Строгий JSON review; некорректный ответ и APPROVE с пробелами в доказательствах → `QUARANTINED`.
- Независимые контексты исполнителя и рецензента, отдельные настройки моделей.
  Это может быть один поставщик Claude; внешняя независимость или криптографическая аттестация не заявляются.
- Бесплатный локальный канал Ollama через `127.0.0.1:11434`, без облачного API-ключа.
  HTTP redirect не выполняется, внешний адрес и proxy для этого адаптера не используются.
- Лимиты суточного числа вызовов и планируемых токенов резервируются в одной транзакции
  с попыткой отправки. Неопределённые попытки расходуют квоту.
- Готовый live-ответ можно явно поставить в существующий GitHub outbox. Автоматической публикации нет.

`COMPLETED` означает, что ответ одобрен AI-рецензентом в выбранном режиме.
В mock-режиме это только симуляция. Это не человеческая приёмка, PR, доказательство
выполнения кода или подтверждение доставки в GitHub.

## Требования и автономная проверка

Python 3.12+, только стандартная библиотека. Устанавливать SDK или сторонние пакеты не требуется.
Работайте в каталоге распакованного пакета. Используйте существующий изолированный
checkout/каталог; не создавайте worktree, если пользователь этого не просил.

```bash
python -m unittest discover -v -p 'test_*.py'
python orchestrator.py --db state.sqlite doctor
python orchestrator.py --db state.sqlite submit --task-id demo-001 --prompt-file examples/task.txt --rubric-file examples/rubric.txt
python orchestrator.py --db state.sqlite work
```

Worker по умолчанию работает только с mock-очередью. Он сам пройдёт четыре шага:
ответ → замечания → исправленный ответ → тестовое одобрение, после чего ожидает новые задачи.
Остановить его можно Ctrl+C. В другом терминале:

```bash
python orchestrator.py --db state.sqlite status --task-id demo-001
```

Ожидается `state=COMPLETED`, `revision=1`, четыре попытки с `provider=mock`.
Для проверки восстановления запустите четыре раза `work --once`: каждый запуск —
отдельный процесс, состояние между ними хранится в SQLite.

Отмена будущей работы: `python orchestrator.py --db state.sqlite cancel --task-id demo-001`.
Уже отправленный HTTP-запрос отменить этим нельзя; он может быть оплачен.

## Локальные модели без платного API

Новый `OllamaAgent` поддерживает локальный Ollama Chat API. Установка Ollama и загрузка
моделей не выполнялись. В текущей облачной машине executable отсутствует,
`127.0.0.1:11434` отвечает отказом в соединении. Не объявляйте это проверкой настоящей модели.

На машине с уже работающим Ollama выберите две установленные модели (можно одну
модель в отдельных контекстах). Укажите их реальные имена, например в Bash:

```bash
export A2A_EXECUTOR_MODEL='имя-установленной-модели'
export A2A_REVIEWER_MODEL='имя-установленной-модели'
python orchestrator.py --db local-state.sqlite doctor --local
python orchestrator.py --db local-state.sqlite submit --task-id local-001 --prompt-file examples/task.txt --rubric-file examples/rubric.txt --mode local --max-revisions 1
python orchestrator.py --db local-state.sqlite work --local
```

В PowerShell вместо `export` используйте `$env:A2A_EXECUTOR_MODEL='...'` и
`$env:A2A_REVIEWER_MODEL='...'`. Остальные команды одинаковы.

Worker обращается только к `http://127.0.0.1:11434/api/chat` на своей машине.
Ollama на Windows-ПК не становится доступен облачной машине через её localhost.
Для такой конфигурации запускайте worker на том же ПК; удалённый транспорт не настроен.
Схема JSON-review та же, число итераций ограничено, модель не получает инструменты.

`doctor --local` проверяет наличие имён моделей, а не доступность сервера/моделей.
Реальный отказ или тайм-аут после резервирования останавливает шаг как UNKNOWN.
Для первого запуска используйте отдельную тестовую задачу и `work --local --once`.
После успешного AI-review команда `stage` может подготовить локальный outbox и для
Ollama, но отмечает `authenticated=False`: локальный идентификатор попытки не доказывает
происхождение модели. Публикацию следует разрешать отдельно.

## Задел настоящего канала Claude — заблокирован политикой бюджета 0

В этой сборке платных запросов не было. Следующие команды не являются текущим
разрешённым сценарием и при неизменной политике вернут BLOCKED. Если пользователь
в будущем отдельно разрешит платный канал, потребуется пересмотр политики в коде.
Одна только настройка ключей его не включает. Технические требования адаптера: через защищённую
конфигурацию среды, не через чат или файлы репозитория:

| Настройка | Назначение |
| --- | --- |
| `ANTHROPIC_API_KEY` | Ключ Anthropic API |
| `A2A_EXECUTOR_MODEL` | Доступный вашему аккаунту идентификатор модели исполнителя |
| `A2A_REVIEWER_MODEL` | Идентификатор модели рецензента |
| `A2A_MAX_CALLS_PER_DAY` | Общий предел вызовов нового orchestrator за сутки UTC |
| `A2A_MAX_PLANNED_TOKENS_PER_DAY` | Общая квота оценочных токенов |
| `A2A_LIVE_APPROVED=YES` | Явное включение live-worker |

Четыре вызова нужны для одного ответа, одного исправления и двух reviews.
Шесть вызовов — верхняя граница одной задачи с двумя исправлениями.
Несколько задач делят суточную квоту в одной БД. Использование другой БД создаёт
отдельную квоту; старые pilot/dispatcher имеют свои квоты и не должны запускаться
параллельно с расчётом на общий лимит нового orchestrator.

Оценка токенов — эвристика. Эти квоты **не гарантируют денежный предел**:
до первого вызова нужны согласованный числовой бюджет и лимиты расходов на стороне
провайдера. `doctor` проверяет только наличие настроек, а не действительность ключа,
цены, авторизацию или установленные ограничения биллинга.

```bash
python orchestrator.py --db live-state.sqlite doctor
python orchestrator.py --db live-state.sqlite submit --task-id pilot-001 --prompt-file examples/task.txt --rubric-file examples/rubric.txt --mode live --max-revisions 1
python orchestrator.py --db live-state.sqlite work --live --once
```

`--once` исполняет ровно один шаг. Используйте его для первоначальной проверки
состояния после каждого платного вызова. `work --live` продолжает разрешённый цикл
автоматически в пределах квоты. Mock-worker не забирает live-задачи и наоборот.

При `UNKNOWN` автоматически повторять задачу, менять её id для обхода блокировки или
сбрасывать квоту нельзя. Проверьте журнал провайдера; встроенного автоматического
разрешения UNKNOWN пока нет.

## Передача результата в GitHub

Только после `COMPLETED` настоящей live-задачи:

```bash
python orchestrator.py --db live-state.sqlite stage --task-id pilot-001
```

Команда только записывает комментарий в локальный outbox. Mock-результаты блокируются.
Публикация — отдельная операция с разрешением пользователя и настроенными
`GITHUB_TOKEN`, `GITHUB_REPOSITORY`, `GITHUB_ISSUE_NUMBER`:

```bash
python outbox.py --db live-state.sqlite publish --task-id pilot-001 --live-publish
```

Этот код ничего не публиковал. Существующий outbox сохраняет неоднозначный результат
POST как `UNKNOWN`. Для сверки используйте `receipt.py` и фактическую учётную запись
GitHub; сам статус `POSTED` не доказывает авторство модели или человеческую приёмку.
Публичный Issue не подходит для частного кода и секретов. Адрес назначения
outbox берёт в момент публикации: проверьте repo/issue перед отправкой.

## Развёртывание и границы

- Для постоянной работы нужен управляемый хост/сервис, сохраняющий БД и запускающий
  `python orchestrator.py --db /absolute/persistent/state.sqlite work --live` из каталога пакета.
  Такой сервис не установлен; опубликованная среда Codex не доказывает постоянную работу.
- При перезапуске незавершённый сетевой шаг станет UNKNOWN после 180 секунд lease,
  а не будет отправлен снова. HTTP timeout — 75 секунд; автоматических HTTP retries нет.
- Резервная копия БД должна учитывать SQLite WAL. Не копируйте один state.sqlite
  во время записи без SQLite backup API или остановки workers.
- CLI предназначен для доверенного локального оператора. Нет публичного HTTP/MCP
  endpoint, Agent Cards, стандартного A2A transport или подключения из произвольного чата ChatGPT.
- Агенты сейчас решают текстовые задачи; не получают shell, доступ к файлам или Autodesk.
  Настоящий инструментальный coding-agent/Windows runner подключается отдельно.
- Не меняются Chrome Bridge, proxy, CODEX_DISABLED, Windows trust store или рабочий runtime.
- Модели могут ошибаться и одобрять неверные ответы; тесты проверяют механизм, не качество
  реального AI-review. JSON, provider id и локальная SQLite-запись не являются внешней аттестацией.

Полная подключённая система ещё требует реального сквозного теста, постоянного
развёртывания, аутентифицированного интерфейса координатора и проверенных исполнителей
с инструментами. Полный исторический README поставленного прототипа сохранён в
`README-v014-HISTORY.md`; его старые ограничения описывают предыдущие команды.
Старые `dispatcher.py`/`pilot*.py` сохранены без изменений для совместимости и тестов;
они имеют собственные live-флаги и не подчиняются новому PAID_API_ALLOWED. Не используйте
их live-режимы: текущий запрет пользователя относится ко всему выполняемому сценарию.
