# Внешние условия сквозного подключения

Проверка 27.10.2026, после публикации исходников v0.16.

## Настоящая модель

1. Ollama v0.40.11 установлен из официального архива, SHA256 совпал с манифестом.
   Сервер отвечает. Загрузка qwen2.5:1.5b остановилась с Forbidden на blob-хранилище.
   Объём частичного/предвыделенного файла не доказывает загрузку; /api/tags пуст.
2. В облачной машине обнаружен Codex CLI 0.163.0. Поддерживаемая проверка
   `codex login status` сообщила ChatGPT-auth, не API-key auth. Это статус локальной
   авторизации, не доказательство действующего удалённого доступа.
3. Короткий текстовый probe с read-only sandbox, отключёнными shell/apps/plugins/
   multi-agent/browser/computer tools и ephemeral context не получил ответа.
   После устранения требования записи runtime/cache повторный запуск дошёл до
   сетевого подключения и получил `HTTP CONNECT failed with status 403`.
   Запуск ограничен 60 секундами и остановлен; автоматического повторного запроса нет.
   Windows runtime и CODEX_DISABLED не менялись. Учётные данные не копировались и не печатались.

Таким образом, ни один вариант ещё не подтвердил настоящий ответ модели.
В сетевом черновике сохранены необходимые домены Ollama/blob и chatgpt.com для
штатного подписочного Codex-канала. Черновик сам по себе не применяет сетевую политику.
После её применения надо повторить только затронутую проверку, без обхода proxy/TLS.
Платные model API остаются запрещены. Подписочный CLI, если заработает, использует
квоту аккаунта; это не обещание безлимитного бесплатного сервиса.

## ChatGPT MCP app

Локальный официальный SDK успешно выполнил MCP initialize/list_tools/health и
создание/чтение/отмену задачи. Это не вызов из пользовательского интерфейса ChatGPT.
CONTROL_PLANE_TUNNEL_ID и CONTROL_PLANE_API_KEY в действующей машине отсутствуют.
Официальный `tunnel-client doctor` завершился с exit=2, missing tunnel ID.

В черновике среды добавлены требования:

- CONTROL_PLANE_TUNNEL_ID — настоящий ID созданного Tunnel.
- A2A_TUNNEL_RUNTIME_KEY → CONTROL_PLANE_API_KEY для HTTPS к api.openai.com.
  Ключ должен иметь Tunnels Read + Use. Секрет вводится только в защищённых настройках.

Создание Tunnel требует доступа владельца к OpenAI Platform и Tunnels Read + Manage.
Приложение нужно установить/разрешить в настройках ChatGPT для того же Tunnel.
Инструменты этой сессии не предоставляют создание Tunnel или управление настройками
аккаунта ChatGPT; runtime/admin key не настроен. Нельзя выдумывать ID, копировать
auth-токены из файлов или объявлять подключение на основании одной локальной проверки.

## Постоянная среда

В черновике сохранены дополненные install_script и start_skill, сохранив прежние
инструкции nss-engine. Новые инструкции фиксируют dependency lock, runtime paths,
запуск Ollama/MCP/UI/tunnel, проверки готовности и незакрытые внешние условия.
Сохранение черновика не означает публикацию, применение сети или перенос live-процессов.

Сквозная версия остаётся НЕФИНАЛЬНОЙ, пока не получены настоящий ответ модели и
подтверждённый вызов соответствующего инструмента из ChatGPT.
