# AGPT/APPT 1.1.0-preview.3 — полный комплект исходников

Это самостоятельный комплект исходников preview.3: проекты плагина, общего ядра, тесты и Windows-сценарии сборки. Установка preview.2 и применение предыдущего патча не нужны. Частные чертежи DWG/DXF, библиотека блоков и Autodesk API DLL в исходники не включены.

## Подготовка и сборка

Нужны Windows x64, .NET 8 SDK и AutoCAD 2026 (.NET 8, API R25.1). Также предусмотрена сборка против AutoCAD 2025 API R25.0; AutoCAD 2024 и старше не поддерживаются. Выбирайте сборку под установленный хост.

Перед запуском BAT восстановите свою оригинальную папку `blocks` согласно [инструкции](blocks/README_SOURCE_ONLY.md). README, пустые файлы с распознаваемыми именами и один файл рамки не проходят проверку. Пустой файл с известным именем отклоняется даже при наличии другого непустого кандидата, чтобы он не перекрывал ресурс при поиске. Проверка требует непустой файл рамки и исходный DWG УГО с распознаваемыми именами; правильность CAD проверяется отдельно в AutoCAD.

Из папки этого комплекта выполните:

```bat
build.bat "C:\Program Files\Autodesk\AutoCAD 2026"
```

Результат: `bin\Release\AGPT.dll`, `AGPT.InputCore.dll` и `blocks`. При переносе сохраняйте обе DLL и ресурсы вместе. Autodesk `AcCoreMgd.dll`, `AcDbMgd.dll`, `AcMgd.dll` берутся из установленного AutoCAD и не распространяются.

Для ручной загрузки откройте новый тестовый DWG в AutoCAD и выполните `NETLOAD`, выбрав `AGPT.dll`. Для запроса запуска нового процесса с NETLOAD после сборки предусмотрен:

```bat
BUILD_AND_RUN.bat "C:\Program Files\Autodesk\AutoCAD 2026"
```

Сообщение о запуске ещё не подтверждает загрузку плагина. `install_bundle.bat` пересобирает и устанавливает bundle для текущего пользователя; закройте AutoCAD перед заменой загруженных DLL. Сценарии не меняют SECURELOAD/TRUSTEDPATHS. Ошибки доверия диагностируйте штатными средствами своего AutoCAD.

## Проверки и ограничения preview

Для независимых от AutoCAD тестов из папки комплекта, с .NET 8 SDK:

```bat
dotnet test tests\AGPT.InputTests.csproj -c Release
```

Предыдущая проверка полных исходников: 107 тестов успешно; сборки против API R25.0 и R25.1 успешны с 5 предупреждениями в каждой. Это не подтверждает работу команд в AutoCAD. Нативные проверки в Windows/AutoCAD и инженерная приёмка остаются обязательными.

Отдельная проверка защиты библиотеки (Windows PowerShell 5.1):

```powershell
powershell.exe -NoLogo -NoProfile -File .\ci\test-resource-preflight.ps1
```

Она разбирает `build.ps1` через AST и выполняет только функцию проверки ресурсов на временных файлах. Сборка и AutoCAD не запускаются. Восемь случаев проверяют отсутствие библиотеки, один README, одну рамку, пустой УГО, пустую приоритетную рамку при наличии непустой альтернативы, пустой приоритетный УГО при наличии непустой альтернативы, только неподдерживаемые локальные имена ресурсов и наличие двух непустых файлов с известными именами. Синтетические байты существуют только во временном каталоге, затем удаляются; они проверяют наличие файлов, а не корректность CAD. Фактический результат запуска этого сценария указывается отдельно в отчёте проверки.

Для первой нативной проверки используйте **отдельные новые DWG для AGPT и APPT**, копии входных данных и восстановленные оригинальные блоки. Заполните реквизиты через `AGPT_PROJECT` или `APPT_PROJECT`, задайте реальные исходные параметры и запускайте соответствующий `AGPT_ALBUM` или `APPT_ALBUM`.

Повторный ALBUM заменяет только ранее созданные этим механизмом объекты с точной меткой своей системы. Старые объекты без метки и результаты отдельных команд `*_SHEET_*` автоматически не заменяются; они могут оставаться в DWG. Проверяйте состав листов и отсутствие наложений. Расчётные прототипы, особенно гидравлика, требуют проверки инженером; успешная компиляция и unit-тесты не разрешают проектный выпуск.

## Готовые сборки из CI

В GitHub Actions откройте успешный запуск **AGPT preview.3 acceptance**, затем скачайте артефакт **AGPT-APPT-1.1.0-preview.3-pilot**. Он содержит этот полный комплект исходников и по две DLL в `Runtime/AutoCAD2025` и `Runtime/AutoCAD2026`. Это кандидат для пилотной проверки, а не подтверждённый в AutoCAD релиз.

Распакуйте архив полностью. Выберите папку Runtime для своего AutoCAD и восстановите **полную оригинальную папку `blocks` непосредственно рядом с обеими DLL**. Для такой ручной загрузки .NET SDK и пересборка не требуются. Откройте отдельный тестовый DWG и выполните `NETLOAD` для выбранного `AGPT.dll`. Не копируйте Autodesk API DLL. Сценарии BAT в корне предназначены для сборки из исходников и используют корневую папку `blocks`.

`SOURCE_SHA256SUMS.txt` фиксирует исходники; `SHA256SUMS.txt` в артефакте также охватывает обе пары скомпилированных DLL и `RELEASE_INFO.json` с коммитом сборки. Проверка хешей подтверждает целостность, но не инженерную корректность.

## Пилотная приёмка в AutoCAD

1. Сохраните исходный DWG без изменений и используйте отдельные рабочие копии для AGPT и APPT.
2. Убедитесь в загрузке preview.3 и наличии команд. Задайте реквизиты PROJECT, зоны, модули и параметры по реальному объекту.
3. Выполните ALBUM. Проверьте фактические планы, рамки, УГО, масштабы, пагинацию, спецификацию и кабельный журнал по исходным данным.
4. Повторите ALBUM в той же копии: предыдущие отмеченные листы своей системы должны замениться без потери исходной геометрии и объектов другой системы. Сравните состав объектов и листов до/после.
5. Попытайтесь выбрать созданную альбомом геометрию как новую зону: операция должна отклоняться без изменения объектов.
6. Сохраните, закройте и откройте копию; проверьте реквизиты, исходные теги и повторную генерацию. Зафиксируйте ошибки командной строки и визуальные дефекты.

До этой проверки и независимой проверки расчётной методики не используйте результат для выпуска рабочей документации. Числа из PDF не подгонялись; расчётные прототипы не получили нормативной аттестации.
