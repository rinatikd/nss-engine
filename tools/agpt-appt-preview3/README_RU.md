# AGPT/APPT 1.1.0-preview.10 — полный комплект исходников

Это самостоятельный комплект исходников preview.10: проекты плагина, общего ядра, тесты и Windows-сценарии сборки. Установка preview.2 и применение предыдущего патча не нужны. Частные чертежи DWG/DXF, библиотека блоков и Autodesk API DLL в исходники не включены.

## Ввод зоны и расчётные данные в preview.10

`AGPT_ZONE` больше не открывает форму ввода. Сразу щёлкните первый угол и обойдите помещение мышью; Enter замыкает контур. Для готовой полилинии выберите вариант «Контур» в запросе первого угла. Предварительный Enter для переключения режима больше не нужен. После выбора запрашивается только высота помещения в метрах; если она есть в модели, предлагается как значение по Enter. Отмена запроса высоты не добавляет новый контур. Esc отменяет захват без новых объектов. Новый контур проверяется на пересечения и корректную площадь. Для явного инженерного редактирования оставлена отдельная команда AGPT_ZONE_EDIT.

Размерность предлагается автоматически по единицам модели, линейным размерам с явной подписью мм/см/м и габаритам помещения. Один размер без единиц не подтверждает масштаб. Габаритная эвристика всегда помечается предварительной; при противоречиях расчёт блокируется. INSUNITS автоматически не меняется. Для unitless DXF допускается согласованный подтверждённый масштаб в метаданных захваченных зон, с проверкой единиц и масштаба труб.

Из исходной модели читаются ROOM_NAME, H_M/HEIGHT_M, FH_M2/OPENINGS_M2, TM_C/MIN_TEMP_C и GOTV в атрибутах блоков внутри контура на той же отметке. Источники сохраняются, изменения и удаление атрибутов учитываются при повторном захвате. Неоднозначные данные не подменяются догадкой. Если данных недостаточно, сохраняется контур с предложением масштаба и статусом INCOMPLETE; автоматический расчёт по нему запрещён. Нельзя достоверно получить высоту, температуру и негерметичность из одних XY-углов.

`AGPT_VERSION` показывает фактически загруженную версию и путь DLL.

Концентрация и плотность доступны только для чтения. Выбор HFC-227ea применяет профиль предоставленного проектного эталона: Cн=7,2 об. %, ρ₀=7,28 кг/м³ при +20 °C и 101,3 кПа. При автоматическом захвате используется явный ГОТВ модели, а при его отсутствии — настроенный пользователем HFC-227ea. Конфликтующие исходные данные не заменяются настройкой. В AGPT_ZONE_EDIT профиль можно применить явно. Источник обозначен как ProjectReference: это значение из приложенного проекта, а не независимо подтверждённая универсальная норма для любых объектов, веществ и пожарных нагрузок. Другие ГОТВ пока не поддержаны.

**K4 и Vтр не являются полями ввода зоны.** Дополнительный множитель K4 из неподтверждённой схемы прототипа удалён: в используемой напечатанной формуле эталона его нет. Программа не выдаёт скрытое K4=1 за нормативное значение. Это изменение расчётной схемы относительно предыдущих preview; результаты для старых зон с K4≠1 могут измениться. Полная инженерная методика, включая остаток в баллонах и модель остатка в трубах, остаётся неподтверждённой.

Vтр вычисляется по исходной сети отдельно для каждой зоны: Σ π/4 × Dвн² × L. Длины берутся из текущей геометрии, Dвн — фактический внутренний диаметр по спецификации трубы, а не номинальный Ду. Сохранённый ручной VTR и старые длины L не используются для этого результата.

Для новых участков `AGPT_PIPE` запрашивает защищаемую зону, типоразмер Ду, фактический внутренний диаметр и точки участка. Пока проверенный каталог типоразмеров не подключён, внутренний диаметр указывается в свойствах трубы по её спецификации. Для старых размеченных участков выполните `AGPT_PIPE_DATA`: выберите участок, зону и уточните внутренний диаметр. Это исходная характеристика трубы; сам объём вводить не требуется.

`AGPT_CALC` и `AGPT_ALBUM` используют один сборщик и один вычисленный Vтр. Неизвестная привязка, отсутствующий внутренний диаметр или смена Ду после гидравлического подбора останавливают расчёт с указанием участка. После смены Ду подтвердите соответствующий внутренний диаметр через `AGPT_PIPE_DATA`. При отсутствии участков явно выводится предупреждение: учтено 0 участков, Vтр=0, модель сети ещё не подтверждена.

Для обновления закройте AutoCAD со старой DLL, распакуйте preview.10 в отдельную папку, восстановите оригинальные blocks рядом с DLL и выполните NETLOAD. Последовательные запросы Cн/K4/Vтр либо открытие формы после AGPT_ZONE означают, что работает старая DLL; проверьте AGPT_VERSION и перезапустите AutoCAD. Историческое имя каталога исходников в GitHub — tools/agpt-appt-preview3; версия отображается при загрузке.

## Подготовка и сборка

Нужны Windows x64, .NET 8 SDK и AutoCAD 2026 (.NET 8, API R25.1). Также предусмотрена сборка против AutoCAD 2025 API R25.0; AutoCAD 2024 и старше не поддерживаются. Выбирайте сборку под установленный хост.

Перед запуском BAT восстановите свою оригинальную папку `blocks` согласно [инструкции](blocks/README_SOURCE_ONLY.md). README, пустые файлы с распознаваемыми именами и один файл рамки не проходят проверку. Пустой файл с известным именем отклоняется даже при наличии другого непустого кандидата, чтобы он не перекрывал ресурс при поиске. Проверка требует непустой файл рамки и исходный DWG УГО с распознаваемыми именами; правильность CAD проверяется отдельно в AutoCAD.

Из папки этого комплекта выполните:

```bat
build.bat "C:\Program Files\Autodesk\AutoCAD 2026"
```

Результат: `bin\Release\AGPT.dll`, `AGPT.InputCore.dll` и `blocks`. При переносе сохраняйте обе DLL и ресурсы вместе. Autodesk `AcCoreMgd.dll`, `AcDbMgd.dll`, `AcMgd.dll` берутся из установленного AutoCAD и не распространяются.

Для ручной загрузки откройте новый тестовый DWG в AutoCAD и выполните `NETLOAD`, выбрав `AGPT.dll`. Для запроса запуска нового процесса с NETLOAD после сборки предусмотрен:

```bat
BUILD_AND_RUN.bat "C:\Program Files\Autodesk\AutoCAD 2026"
```

Сообщение о запуске ещё не подтверждает загрузку плагина. `install_bundle.bat` пересобирает и устанавливает bundle для текущего пользователя; закройте AutoCAD перед заменой загруженных DLL. При установке bundle выбирается только версия AutoCAD, против API которой выполнена сборка: 2025/R25.0 либо 2026/R25.1. Все три API-библиотеки должны иметь одинаковую пару major/minor. Установленный bundle не объявляет совместимость со второй версией хоста. Повторная установка для другого хоста заменяет bundle текущего пользователя. Сценарии не меняют SECURELOAD/TRUSTEDPATHS. Ошибки доверия диагностируйте штатными средствами своего AutoCAD.

## Проверки и ограничения preview

Для независимых от AutoCAD тестов из папки комплекта, с .NET 8 SDK:

```bat
dotnet test tests\AGPT.InputTests.csproj -c Release
```

Предыдущая проверка полных исходников: 288 тестов успешно; сборки против API R25.0 и R25.1 успешны с 5 предупреждениями в каждой. Это не подтверждает работу команд в AutoCAD. Нативные проверки в Windows/AutoCAD и инженерная приёмка остаются обязательными.

Отдельная проверка защиты библиотеки (Windows PowerShell 5.1):

```powershell
powershell.exe -NoLogo -NoProfile -File .\ci\test-resource-preflight.ps1
```

Она разбирает `build.ps1` через AST и выполняет только функцию проверки ресурсов на временных файлах. Сборка и AutoCAD не запускаются. Восемь случаев проверяют отсутствие библиотеки, один README, одну рамку, пустой УГО, пустую приоритетную рамку при наличии непустой альтернативы, пустой приоритетный УГО при наличии непустой альтернативы, только неподдерживаемые локальные имена ресурсов и наличие двух непустых файлов с известными именами. Синтетические байты существуют только во временном каталоге, затем удаляются; они проверяют наличие файлов, а не корректность CAD. Фактический результат запуска этого сценария указывается отдельно в отчёте проверки.

Для первой нативной проверки используйте **отдельные новые DWG для AGPT и APPT**, копии входных данных и восстановленные оригинальные блоки. Заполните реквизиты через `AGPT_PROJECT` или `APPT_PROJECT`, задайте реальные исходные параметры и запускайте соответствующий `AGPT_ALBUM` или `APPT_ALBUM`.

Повторный ALBUM заменяет только ранее созданные этим механизмом объекты с точной меткой своей системы. Старые объекты без метки и результаты отдельных команд `*_SHEET_*` автоматически не заменяются; они могут оставаться в DWG. Проверяйте состав листов и отсутствие наложений. Расчётные прототипы, особенно гидравлика, требуют проверки инженером; успешная компиляция и unit-тесты не разрешают проектный выпуск.

## Готовые сборки из CI

В GitHub Actions откройте успешный запуск **AGPT preview.10 acceptance**, затем скачайте артефакт **AGPT-APPT-1.1.0-preview.10-pilot**. Он содержит этот полный комплект исходников и по две DLL в `Runtime/AutoCAD2025` и `Runtime/AutoCAD2026`. Это кандидат для пилотной проверки, а не подтверждённый в AutoCAD релиз.

Распакуйте архив полностью. Выберите папку Runtime для своего AutoCAD и восстановите **полную оригинальную папку `blocks` непосредственно рядом с обеими DLL**. Для такой ручной загрузки .NET SDK и пересборка не требуются. Откройте отдельный тестовый DWG и выполните `NETLOAD` для выбранного `AGPT.dll`. Не копируйте Autodesk API DLL. Сценарии BAT в корне предназначены для сборки из исходников и используют корневую папку `blocks`.

`SOURCE_SHA256SUMS.txt` фиксирует исходники; `SHA256SUMS.txt` в артефакте также охватывает обе пары скомпилированных DLL и `RELEASE_INFO.json` с коммитом сборки. Проверка хешей подтверждает целостность, но не инженерную корректность.

## Пилотная приёмка в AutoCAD

1. Сохраните исходный DWG без изменений и используйте отдельные рабочие копии для AGPT и APPT.
2. Убедитесь в загрузке preview.10 и наличии команд. Задайте реквизиты PROJECT, зоны, модули и параметры по реальному объекту.
3. Выполните ALBUM. Проверьте фактические планы, рамки, УГО, масштабы, пагинацию, спецификацию и кабельный журнал по исходным данным.
4. Повторите ALBUM в той же копии: предыдущие отмеченные листы своей системы должны замениться без потери исходной геометрии и объектов другой системы. Сравните состав объектов и листов до/после.
5. Попытайтесь выбрать созданную альбомом геометрию как новую зону: операция должна отклоняться без изменения объектов.
6. Сохраните, закройте и откройте копию; проверьте реквизиты, исходные теги и повторную генерацию. Зафиксируйте ошибки командной строки и визуальные дефекты.

До этой проверки и независимой проверки расчётной методики не используйте результат для выпуска рабочей документации. Числа из PDF не подгонялись; расчётные прототипы не получили нормативной аттестации.

Отдельный сценарий `ci/test-bundle-host.ps1` проверяет 11 случаев выбора API и формирования XML bundle: оба хоста, допустимые различия patch-версий, смешанные/неподдерживаемые/неполные API-наборы и неполные манифесты. Выполняется Windows PowerShell 5.1 в CI, без запуска сборки или AutoCAD.

Гидравлический сборщик также использует текущие длины, исключает объекты альбома и проверяет исходные единицы. Пересчёт гидравлики не перезаписывает происхождение единиц: смена INSUNITS требует явной проверки свойств трубы.

Автосбор также читает DBText/MText с явными подписями внутри помещения на той же отметке: H=3 м, «Высота помещения: 3000 мм», Tmin=20 °C, FH=0,2 м², «ГОТВ: Хладон 227еа», «Помещение: Электрощитовая». Голые числа, произвольные слова и противоречивые значения не становятся фактами. Это не универсальное распознавание таблиц, XREF или неструктурированного текста. Из пустого прямоугольника физические параметры получить невозможно.

Сообщения основного автоматического режима описывают отсутствующие в модели данные и не предлагают вводить их вручную. Зависимые Cн/плотность не дублируют отсутствие ГОТВ. Параметры не подставляются из произвольных типовых значений.

Минимальная температура по явному требованию пользователя — 20 °C, если в модели нет корректного и непротиворечивого значения. Источник помечается UserConfiguredDefault20C; это настройка, а не распознанный факт. Существующее значение из модели сохраняется; конфликт или повреждённое значение не заменяется молча на 20. Температуру можно изменить отдельно командой AGPT_TEMPERATURE, выбрав контур; полный ввод остальных параметров не требуется. Явные правки помечаются ManualOverride и не сбрасываются при повторном автоматическом захвате. Если в модели позже появляется явная температура, она имеет приоритет над настройкой по умолчанию, но не над ручной правкой.

AGPT_TEMPERATURE изменяет только температуру и её происхождение, с отменой без записи. Проверка готовности обновляется и для неполного помещения. AGPT_ZONE_EDIT помечает ManualOverride только действительно изменённые поля, сохраняя автоматическое обновление остальных.

## ГОТВ по умолчанию в preview.10

Если в модели не указан ГОТВ, AGPT_ZONE применяет HFC-227ea по настройке пользователя и отмечает происхождение значения. Явно заданный другой газ сохраняется и проходит проверку поддерживаемости; противоречивые данные не заменяются значением по умолчанию. При повторном захвате актуальные данные модели имеют приоритет над прежним значением по умолчанию. Cн и плотность берутся из существующего проектного профиля, их применимость к объекту требует инженерной проверки.

Пользователь установил FH=0,011 м² как проектное допущение по умолчанию. Это площадь, не объём и не универсальный нормативный минимум. Значение применяется только при отсутствии исходного факта и конфликта; явное FH=0 сохраняется. Исправление: AGPT_OPENINGS.

## Диагностика масштаба в preview.10

AGPT_ZONE выводит коэффициент м/ед. и габариты ограничивающего прямоугольника XY в метрах. Эти габариты не являются длинами стен повёрнутого или непрямоугольного помещения. INSUNITS без независимых размерных данных обозначает принятое объявление единиц, а не доказательство реальных размеров. Диагностика не изменяет координаты, INSUNITS или правила допуска расчёта и не добавляет запросов. Маленькая площадь сама по себе не доказывает ошибку масштаба.

## Перенос полезных доработок в preview.10

После выбора углов требуется только высота; HFC-227ea, Tм=20°C и FH=0,011 м² применяются как пользовательские настройки при отсутствии явных данных. Старый автоматический default 18 °C заменяется на 20 °C при повторном захвате; явная ручная настройка 18 °C сохраняется. Противоречия не перекрываются настройками.

- AGPT_OPENINGS — исправление площади проёмов отдельной зоны; AGPT_TEMPERATURE — температуры.
- AGPT_ZONE_LIST — исходные зоны, S/H/Vp/FH/Tм/ГОТВ и статус, без представления старой массы как текущей.
- AGPT_ZONE_LABEL — обновление собственной подписи зоны по GUID и handle. Захват и редактирование также обновляют её; неопределённый масштаб не должен оставлять старую подтверждённую подпись. Это сохранённое представление данных; после непосредственной правки геометрии повторите AGPT_ZONE.
- AGPT_CALC — общий сборщик и атомарная запись исторических CALC_SNAPSHOT_* с датой UTC. Эти данные не подменяют исходные свойства и не используются как автоматически актуальная масса в гидравлике.
- Общая рабочая область листа с резервом72мм над штампом, исправлено положение таблицы и примечаний структурной схемы. Сохранены пагинация и реальные данные модели; существующие две колонки общих данных и зазор80мм между A3 не заменены демонстрационной версией.
- Импорт УГО сообщает числа загруженных, имеющихся, отсутствующих и ошибочных блоков.

Блоки DWG/DXF из предоставленного локального архива используются как частные ресурсы рядом с DLL; публичный пакет не распространяет эти чертежи. Некоторые имена в архиве имеют повреждённую кодировку: восстановите имена ожидаемых файлов перед проверкой импорта. Нативное оформление и расчётная методика требуют проверки.
