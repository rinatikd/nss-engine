# NSS Engine

Исходники инструментов AutoCAD для ТКК, СВН и диагностики NSS. Основной рабочий ПК сохраняет полный инженерный каталог; GitHub содержит отобранный код и переносимые инструкции. Исходные чертежи, расчётные выгрузки, дистрибутивы и локальные окружения в Git не входят.

## Актуальные исходники

- `work/NSS_TKK_Editor_v0.2/`: текущая рабочая база редактора ТКК и модуля CCTV. `source/` — C# add-in; `engine/` — расчёт; `modules/cctv/` — видимость, DORI, архив и CLI; `tests/` — тесты; `native/` — исходники нативных сценариев; `scripts/` — подготовка и сборка. Имя каталога историческое; текущий csproj объявляет версию 0.2.3 и содержит CctvCommands.cs.
- `work/NSS_AutoDebug_v0423/`: отдельная ветка разработки диагностического NSS Engine v0.42.3: `autocad/`, `nss_engine/`, `scripts/`, `tests/`, `contract_tests/`. Она не заменяется автоматически редактором ТКК и не смешивается с его версиями.
- `work/*.py`: авторские скрипты сборки, аудита и исследования исходных чертежей. Часть относится к прежним выпускам и требует локальных входов; это не автоматические команды запуска.
- `tools/cctv/`: последние авторские построители комплекта СВН v09 и углового варианта. Требуют локальных закрытых инженерных входов; их ограничения описаны рядом.
- `.agents/skills/`: обычные переносимые файлы навыков. SDK, глобальные настройки и машинные API-справочники сюда не включаются.

## Проверка на чистом клоне

Нужен Python 3.12+; выбранные синтетические тесты требуют ezdxf/networkx/shapely, но не AutoCAD и не частных чертежей.

```powershell
python -m pip install -r requirements-test.txt
python tools/repo_guard.py --tree HEAD
python tools/run_portable_checks.py
```

Это автономная проверка исходников. Полные проверки реальных DWG, нативного интерфейса и оборудования требуют частных данных/установленного Autodesk и не подтверждаются зелёным CI.

Для редактора AutoCAD нужен AutoCAD 2026 API и .NET 8 Windows SDK/reference pack. Текущий Revit на основном ПК — 2023 / .NET Framework 4.8; готового подключённого Revit MCP в репозитории нет. Локальная Python-среда для геометрических сборок создаётся отдельно; код использует ezdxf, shapely и scipy, а отчёты могут требовать дополнительные библиотеки. Не копируйте существующее окружение в Git.

## Работа двух агентов

Главный ПК — основной. Второй агент создаёт отдельный clone/worktree и ветку `agent/<имя>/<задача>` от актуальной основной ветки origin. Изменения возвращаются отдельным коммитом/PR; основную ветку обновляет владелец главного ПК. Нельзя переключать ветки в занятом рабочем каталоге, выполнять force push, reset --hard или удалять локальные результаты для очистки дерева.

Перед работой читать AGENTS.md, docs/SOURCE_MAP.md и docs/PORTABLE_SKILLS.md. Проверка перед коммитом включается локально: `git config core.hooksPath .githooks` (репозиторий содержит hook, не меняет глобальные hooks).

Распределение задач между моделями, подтверждённые результаты и оценка приёмки: [совместный цикл 24.10.2026](docs/MULTI_AGENT_REVIEW_2026-10-24.md). Каждый агент работает в своей ветке/worktree; координатор отдельно проверяет результат до интеграции.

## Первый push

Remote: https://github.com/rinatikd/nss-engine.git. История и видимость удалённого репозитория должны быть проверены перед публикацией. `tools/Publish-Prepared.ps1` сначала fetch-проверяет origin и сканирует коммит. Если удалённый репозиторий пуст, публикует main. Если в origin уже есть другая история, публикует только отдельную bootstrap-ветку без перезаписи основной ветки; далее нужна сверка/PR. Force push и автоматическое объединение несвязанных историй не используются.
