# Chrome Bridge 0.2.1-rc.2 — финальная упаковка кандидата

Дата: 30.10.2026. Статус: исходный релиз-кандидат для локальной приёмки,
не stable-релиз и не подтверждённая полная A2A-система.

## Что поставляется

- 74 проверяемых по исходным манифестам файла: Node.js-сервер, MCP stdio,
  MV3-расширение, Hub, шаблоны, тесты и Windows wrapper.
- `CANDIDATE_READY.json` с неизменёнными признаками SOURCE_ONLY_CANDIDATE,
  nativeWindowsVerified=false и liveWebsitesVerified=false.
- `SHA256SUMS.txt`: 75 записей, покрывающих все исходники и metadata;
  сам список исключён. Итого 76 файлов в автономной поставке.
- `RELEASE_CANDIDATE_RU.md`: актуальная русская инструкция с раздельными
  каталогами RC1/RC2 и регистрациями MCP, установкой, проверкой и откатом.

Состояние пользователя, ключи, браузерные профили, node_modules, EXE/DLL,
рабочие журналы и Git-история не поставляются. Бюджет платных API остаётся 0.

## Изменения последней упаковки

Добавлен генерируемый манифест файлов, проверка его полноты и резервирование
его имени против коллизий исходных манифестов. Удалена ошибочная рекомендация
настроить RC2 в каталоге состояния RC1. Исправлены устаревшие команды и ссылки.
Runtime и протокол не менялись; версия сохранена 0.2.1-rc.2.

Сборщик из корня репозитория:

```powershell
node tools/chrome-bridge-rc1/build-source-candidate.mjs --output "C:\путь\новая-папка-RC2"
```

Не запускать поверх существующего каталога. Ветка:
`agent/codex/chrome-bridge-rc1` (историческое имя, пакет RC2).
Скачиваемый source artifact создаётся GitHub workflow Chrome Bridge acceptance
только после всех матричных и синтетических проверок; точный commit и ZIP digest
находятся на странице соответствующего run. В main не выполняется push,
тег stable не создаётся, действующая установка не заменяется.

## Свидетельства и границы

До последней упаковки на commit 3d8c7a1 CI 40937637445 прошёл Windows/Linux,
Node 22/24, отдельные Windows wrapper smoke и синтетический MV3 E2E.
Последний локальный прогон кандидата: 232 теста, 218 PASS, 14 SKIP, 0 FAIL.
Текущие проверки сборщика и установщика: 41 тест, 35 PASS, 6 Windows-only SKIP.
Новый commit упаковки должен иметь собственный зелёный CI; старый run не
подтверждает его автоматически.

Нативный Codex CLI → MCP → веб-Claude проверялся оператором на RC1.
Последний переданный лог RC2 показывает connected=true и pendingQueue=0,
но claudeTabs=0 и agentBindingCount=0. Активные grants и разрешение сайта
не создают вкладку и привязку. По этим данным обмен RC2 ещё не доказан.
actions=false записывается как наблюдение; включать все browser actions ради
agent Control автоматически не требуется.

14 пропусков связаны с дополнительными native/isolation/pilot возможностями.
Шесть из них — пустые тестовые заготовки, требующие реализации, а не только
артефактов. `CODEX_DISABLED` сохранён. Эти возможности не заявляются готовыми
в составе браузерного релиз-кандидата.

## Следующий этап на основном ПК

Не пересобирать уже полученный изолированный пакет без необходимости.
Сохранить работающий RC1 на 17383. В уже подготовленном отдельном профиле RC2
открыть безвредную беседу Claude, выполнить agent_list, agent_bind и selftest
именно через MCP RC2. Проверить соответствие endpoint/manifest/server/client
одному порту (17384 для предоставленного изолированного варианта).
Grant выдаётся человеком в локальном интерфейсе расширения.

Выполнить один явный SendTest, сохранить обезличенный результат и проверить
Stop/revoke/replay. Не повторять UNKNOWN-отправку автоматически. Для каждого
заявленного провайдера нужна собственная реальная приёмка; пока нельзя
объявлять живые Gemini/DeepSeek проверенными. ChatGPT app/tunnel и встроенный
исполнитель Codex не входят в подтверждённую готовность этого кандидата.
