# PowerShell Direct — расширенный инженерный канал

Статус: исходники PR #110, НЕ установлен на Work PC, Windows E2E НЕ выполнен. Работающий сервис 17486 и туннели не затронуты.

## Новые MCP-инструменты

powershell_engineering_submit: requestId, operation, workspace, optional target, scriptArgs, pid, port.
powershell_engineering_status: requestId.

Операции:
- git-status, git-diff, git-log: диагностика кода и коммитов
- node-test: запуск выбранного Node теста
- node-script: выбранный JavaScript скрипт и параметры
- powershell-script: выбранный .ps1 скрипт и параметры
- dotnet-build, dotnet-test: выбранный проект или решение
- process-inspect: read-only сведения об указанном PID
- port-inspect: read-only сведения об указанном TCP порте

Цель — самостоятельно формировать инженерные задания, отправлять на ПК, получать exitCode и ограниченный stdout/stderr, уточнять и повторять только НОВЫЕ осмысленные запросы. Нельзя автоматически повторять UNKNOWN с прежним requestId.

## Разрешения

- Команды выполняются в точных рабочих каталогах, заранее разрешённых локальной конфигурацией PS_DIRECT_ENGINEERING_WORKSPACES; клиент не может менять этот список
- Задание получает долговременную запись в PS_DIRECT_ENGINEERING_AUDIT_DIR до исполнения
- Каждая операция требует реального локального Approve once или Deny с SHA256 плана, конкретной командой и аргументами; текст модели не подтверждает её
- Запуск без shell, фиксированные системные исполняемые файлы; без унаследованных ключей Bridge и туннелей
- Для скриптов и проектов SHA256 основного файла включён в подтверждаемый план; при изменении основного файла запуск отклоняется
- Запуск тестов и сборок — потенциальное исполнение произвольного проектного кода, а НЕ read-only; запрещено считать результат безопасным только из-за названия операции
- Тайм-аут, верхний предел вывода, маскирование типовых секретов. Полную защиту от утечки произвольного stdout без полноценного sandbox нельзя гарантировать
- Отдельная авторизация необходима для production, удаления данных, изменения секретов и остановки процессов; такие операции не предоставлены новому API автоматически

## Установка с минимальным риском

1. Обновить чистый платформенный checkout.
2. Запустить tools/powershell-direct/Stage-EngineeringDirect.ps1 -Mode Inspect, затем Stage. Он проверяет исходники тестами, создаёт C:\Engineering\PowerShellDirect-Engineering-Lab-R1 и повторно прогоняет тесты, не трогая существующий порт 17486 и туннель 18086.
3. Провести на Windows реальные DENY, ALLOW, STATUS, DUPLICATE, проверку ограничений путей и скриптов.
4. Подготовить и отдельно согласовать переход действующего супервизора на новую версию, с rollback и сохранением прежних credentials.
5. Обновить обнаружение инструментов в ChatGPT. Проверить реальный вызов новых MCP submit/status из текущего чата.
