# PowerShell Direct — расширенный инженерный канал

**Новая модель рабочих каталогов (ветка per-job-workspace-approval):** постоянный список разрешённых папок удаляется. Каталог выбирается отдельно для каждой операции, канонизируется на ПК и включается в неизменяемый план локального подтверждения. Это изменение пока находится в исходниках новой feature-ветки; работающий Windows service ещё не обновлён, Windows E2E новой реализации не выполнен.

## Новые MCP-инструменты

- `powershell_engineering_submit`: `requestId`, `operation`, `workspace`, необязательные `target`, `scriptArgs`, `pid`, `port`.
- `powershell_engineering_status`: чтение уже существующего результата, без запуска или повтора.

Операции остаются структурированными: Git status/diff/log/branch/diff-check/ff-only pull; Node test/script; PowerShell script; .NET build/test; process/port inspect. Сырой shell command не принимается.

## Модель доступа к workspace

1. Клиент передаёт абсолютный путь к каталогу в текущей задаче. Постоянный `PS_DIRECT_ENGINEERING_WORKSPACES`, `PS_DIRECT_NAMED_SUITE_WORKSPACES` и родительский `PS_DIRECT_ALLOWED_ROOT` больше не являются политикой доступа.
2. Windows-сервис сам разрешает путь через `realpath`, проверяет, что это существующий каталог, и показывает именно канонический путь в карточке локального подтверждения.
3. Канонический `cwd` включается в fingerprint плана. Подтверждение привязано к точному `requestId` и SHA-256; другой каталог означает другой план и требует нового подтверждения.
4. Запрещаются корни томов, системные каталоги Windows/Program Files и UNC/device-пути. Для обычных локальных каталогов доступ определяется Windows ACL текущего пользователя, а не вручную поддерживаемым списком путей.
5. Изменение/подмена каталога после подтверждения проверяется повторной канонизацией перед запуском.

## Остальные ограничения остаются

- Каждая операция требует локального Approve once или Deny с точной командой, аргументами, canonical workspace и SHA-256 плана.
- ChatGPT plugin permission остаётся **Always ask**; локальное подтверждение не заменяется сообщением модели.
- Фиксированные абсолютные executable paths, `shell:false`, типизированные операции; нет произвольных PowerShell команд/строк.
- Для скриптов и проектов SHA-256 основного файла включён в подтверждаемый план и перепроверяется перед запуском.
- Durable one-shot requestId claim, at-most-once, неизвестный результат не повторяется автоматически.
- Ограниченные и редактируемые stdout/stderr, тайм-аут и остановка дерева дочерних процессов.
- Аудит хранится отдельно в `PS_DIRECT_ENGINEERING_AUDIT_DIR`; секреты и полный environment не попадают в логи.
- Тесты и сборки могут исполнять код проекта; они не становятся безопасными только из-за названия операции.

## Установка и приёмка

Новая политика должна пройти Node unit/integration suite, PowerShell 5.1 syntax checks, Windows staging, локальные DENY/ALLOW, повтор requestId, изменение пути после approval, контроль системных/UNC путей, проверку audit и rollback. Только после отдельного контролируемого обновления supervisor и rediscovery MCP tools можно утверждать, что функция установлена.

Production Chrome Bridge 17381/17382, его credential/tunnels и PR102 Lab 17484 не входят в область изменения.
