# PowerShell Direct: управляемые задания тестирования и сборки

**Статус: интеграция в исходный код PowerShell Direct подготовлена в платформенной ветке; локальный MCP-сервис на Work PC НЕ обновлён, новые команды там НЕ обнаружены и E2E новой операции НЕ подтверждён.**

## Принцип
Открытый PowerShell или выполнение команд из текста модели **не требуется**. Для автоматизации предусмотрены именованные сценарии с фиксированными бинарниками и аргументами. Пользовательский ввод ограничен `requestId`, `suite` и точным разрешённым каталогом `workspace`. Подтверждение исполнения происходит **отдельно в локальном UI Windows**, а не по логическому флагу в запросе модели.

### Файлы
- `tools/ai_collaboration/local_test_runner.mjs` — проверка имени задания, канонического рабочего каталога, запуск без shell, ограниченный вывод, остановка дерева процессов при тайм-ауте.
- `tools/ai_collaboration/local_job_service.mjs` — эксклюзивная долговременная запись requestId до допуска к исполнению, fingerprint задания, ответ локального подтверждения, аудит и статус. Не повторяет неопределённое исполнение.
- `tools/ai_collaboration/local_mcp_dispatch.mjs` — две схемы/обработчика для MCP host: `powershell_named_suite_submit` и `powershell_named_suite_status`.
- `*.test.mjs` — отрицательные проверки разрешений, подмены параметров, повторного выполнения, изоляции пути и очистки.

## Интеграция существующего PowerShell Direct из PR #108

В платформенную ветку импортированы `tools/powershell-direct/{service,runner,stack-supervisor,mcp-stdio,mcp-only-gateway}.mjs` из Draft PR #108, а также исходные тесты. `service.mjs` теперь регистрирует два новых MCP-инструмента при явном включении именованных заданий, а существующие `powershell_propose`, `powershell_cancel`, `powershell_job`, `powershell_chat_readonly` сохраняются.

`stack-supervisor.mjs` использует две новые **локально задаваемые** переменные окружения:

- `PS_DIRECT_NAMED_SUITE_WORKSPACES` — полный список точных разрешённых каталогов, разделённых `;`, например один изолированный checkout `C:\\Engineering\\ChromeBridge-PR113-Lab`.
- `PS_DIRECT_NAMED_SUITE_AUDIT_DIR` — отдельная папка журналов с ограниченными правами.

Без этих переменных функция остаётся **выключена**. Выбранный каталог должен находиться внутри ранее разрешённого `PS_DIRECT_ALLOWED_ROOT`, иначе запуск прекращается. Подтверждение запрашивается через существующую локальную страницу `/approve`, **никогда не через удалённый `/mcp`**.

**Порядок внедрения:** создать отдельную проверенную копию файлов; проверить SHA и наличие/отсутствие конфликтов, выполнить Node tests, дать локальное разрешение на изменение только экземпляра 17486, затем перезапустить именно локальный supervisor с контролем здоровья 18086. Текущие локальные изменения в других файлах не стирать и не перезаписывать.

## Контракт подключаемого MCP хоста
1. Выполнять проверку личности сессии, прав пользователя и локального разрешения на действие. Передать сервису `approveRequest({requestId, suite, workspace, planSha256, operation})`. Подтверждение должно иметь тот же requestId и planSha256 и выдаваться только из настоящего локального UI. Нельзя автоматически подтверждать вызовы из ChatGPT.
2. Создать `createLocalJobService({approvedWorkspaceRoots, auditDirectory, approveRequest})`. Каталоги задаются локальной доверенной конфигурацией, не запросом клиента.
3. Получить `NAMED_SUITE_TOOLS` и `createNamedSuiteHandlers(service)`, зарегистрировать обе операции в **локальном** MCP-сервере, не открывая дополнительный публичный порт.
4. Установить права приложения ChatGPT на выполнение с подтверждением; обновить обнаружение инструментов; проверить, что именно новые имена появились в ChatGPT.
5. Провести DENY, затем ALLOW для отдельного requestId, тест status, повтор того же requestId (без повторного запуска), отказ при другом workspace, тайм-аут и восстановление. Повторять неидемпотентный UNKNOWN запрещено.
6. Протоколировать версию исходника, хеш команды, результат, exitCode, elapsed time, время, усечённый/редактированный вывод, ID артефактов. Никаких токенов, полных переменных окружения, приватных данных в публичных PR.

**Важные ограничения:** код интегрирован в платформенную GitHub-ветку, но НЕ развернут в текущий работающий процесс `stack-supervisor.mjs` на Windows. Файлы текущей установки и её локальные изменения не перезаписывались. Для настоящей интеграции потребуется обновить именно этот локальный сервис из изолированной проверенной копии; нельзя перезаписывать текущие 11 локально изменённых файлов. Не менять production 17381/17382, токены, туннель и PR102 17484.
