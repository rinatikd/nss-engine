# NSS: доведение трёх компонентов — 30.10.2026

База: main `ac6eb0495307506c1bb80b0d5389af06944ef18a`.
Рабочая ветка: `agent/codex/nss-productization-20261030`.
Статус: исправленный исходный кандидат; финальный выпуск требует новой нативной
приёмки. Исторические результаты прежних DLL не переносятся на эти исходники.

## Проверки

- ТКК: 38 синтетических Python-тестов; 28 проверок реальной границы C# → Python,
  включая отказ поворота, отмену процесса, timeout и ошибочные ответы.
- CCTV: 23 теста; независимый разбор ezdxf, кириллица, масштаб, clipped geometry,
  ошибочные CLI при обычном Python и -O, сохранение существующего выхода.
- AutoDebug: 22 чистые проверки C#, 261 Python-тест с C#-fixture; `--prepare`
  на чистых исходниках прошёл без RuntimeFixture, собрал отдельную DLL и проверил
  ровно две уникальные AutoCAD-регистрации. Фаза PREPARED не означает запуск CAD.
- Оба AutoCAD-плагина скомпилированы против API AutoCAD2026 / .NET8:
  0 ошибок и 0 предупреждений. Это кросссборка, не NETLOAD.
- Сводный runner расширен: вместо 27 ранних AutoDebug-проверок использует
  полноценный компонентный набор. Без явно созданного C#-fixture один
  межъязыковой тест прозрачно пропускается; CI создаёт fixture отдельным шагом.
- Частные ТКК drawing snapshots и AutoDebug examples snapshot/plan не включены.
  Их проверки не подменены синтетическими PASS.

Проверки выполнены с Python3.12, .NET SDK8.0.427. В локальном тесте worker
использовался временный Python-wrapper для видимости установленного кеша
зависимостей при -E/-s; в CI передаётся обычный setup-python executable с
установленными requirements. Производственный путь runtime/python.exe не менялся.

Три помощника работали по отдельным компонентам. Четвёртый провёл независимое
read-only ревью. Он нашёл остаточное переполнение CCTV после первой правки;
после исправления отдельно подтвердил три сценария отказа, сохранность файла
и отсутствие временных остатков. Сам координатор проверил интеграцию и запуск
автономных контрактов. Это не рецензия внешнего Claude через Chrome Bridge.

ТКК пока сохраняет привязку к разрешённой рабочей копии проекта и protected
numbering; не ослаблять эту защиту ради открытия произвольного DWG. CCTV остаётся
плоским расчётом прямых препятствий с дискретными лучами: ARC/bulge, 3D/OCS,
XREF/вложенные блоки, старые входные кодировки и нормативы РК требуют отдельных
решений и испытаний. Не объявлять эти возможности реализованными.
