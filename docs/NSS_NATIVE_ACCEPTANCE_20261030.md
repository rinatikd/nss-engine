# Задание основному ПК: нативная приёмка NSS

Работать из отдельного clone/worktree ветки
`agent/codex/nss-productization-20261030` репозитория rinatikd/nss-engine.
Не переключать занятый основной репозиторий и не заменять установленную DLL.
Прочитать AGENTS.md и NSS_PRODUCTIZATION_20261030.md. Продолжать по фактической
версии исходников и хешам, а не по названию старого ZIP.

## Общие действия

1. Проверить AutoCAD2026 x64, SDK8 и Python. Создать отдельное окружение с
   requirements-test.txt; не переносить Python runtime из облачной Linux-среды.
2. Выполнить tools/run_portable_checks.py. Затем запустить оба чистых C# набора
   так же, как в .github/workflows/source-checks.yml. C# контрактные приложения
   запускаются через dotnet run, это не проекты Microsoft.NET.Test.Sdk.
3. Собрать оба плагина, передавая AutoCADDir реального хоста. Сохранять DLL,
   журналы, исходный commit и хеши в отдельном каталоге проверки. Не менять
   SECURELOAD/TRUSTEDPATHS. Не закрывать пользовательские документы.

## ТКК

Сначала подготовить отдельный комплект с НОВОЙ DLL в plugin/, текущим engine/,
Windows runtime/python.exe и разрешёнными проектными protected_numbers.json.
Эти частные ресурсы не входят в публичный исходный репозиторий. Сохранить
фактические зависимости и их версии; старый runtime можно использовать только
после проверки, но старую DLL/engine — не выдавать за новую сборку.

Взять копию разрешённого рабочего DWG. Скрипт prepare_loader.py проверяет состав
комплекта и создаёт loader без изменения настроек безопасности. Выполнить
native-сценарии из native/ и scripts/ на этой копии: добавление/перенос/удаление,
Idle update, один Undo/Redo, переключение/закрытие документов, отмена worker,
save/reopen. Отдельно проверить круглые и симметричные блоки: сериализация
проходит, исходные координаты и Rotation неизменны. Убедиться, что новый
worker/engine хеш связан с сохранёнными результатами. Сверить печать и подписи.
Не устранять автоматически 29 проектных предупреждений как программные ошибки.

## CCTV / СВН

Начать с синтетического прямоугольного помещения и камер с кириллическими
именами. Выпустить DXF в мм и м, открыть оба в AutoCAD, сверить ожидаемые
физические размеры подписи и конуса, clipping на стенах и читаемость атрибутов.
Проверить отказ при пустом CSV, некорректном фокусе/координате, out=plan и
переполнении; исходный файл и прежний результат должны сохраняться.

Далее только отдельная копия подготовленного проектного DXF/CSV. Не менять
согласованную схему размещения, число камер/шкафов или монтажные решения ради
прохождения проверки. Паспортные параметры и нормативные допущения проверить
отдельно; 2D visibility не означает нормативное соответствие всей системы.

## AutoDebug

Из work/NSS_AutoDebug_v0423 выполнить штатный scripts/autodebug_v0421.py
с --prepare и --autocad-dir установленного AutoCAD. Он создаёт новую
девятиобъектную синтетическую fixture и уникальную сборку/регистрацию. Не нужен
пользовательский DWG и не нужно подставлять отсутствующий RuntimeFixture.

После автономной проверки использовать Start-In-AutoCAD.cmd и полученный
RUN_IN_AUTOCAD.lsp по инструкции компонента; запускать только созданную fixture.
Собрать результат штатным Collect-Last-Result.cmd. PREPARED, отсутствие отчёта
и истечение timeout — не PASS. Для приёмки нужны native_results, snapshot,
связанный Python job и проверка collect с правильным run_id и хешами. Старый
native_smoke_v042.py относится к0.42.0 и не заменяет этот цикл0.42.3.

## Возврат координатору

Сохранить по компоненту: commit, фактические команды и exit codes, версии
хоста/SDK/runtime, хеши DLL/engine, пройденные сценарии, неизменность исходника,
остаточные ошибки и визуальную оценку. В Git публиковать только обезличенный
текстовый итог; DWG, дампы, ключи и приватные отчёты остаются на основном ПК.
Не объявлять stable-релиз, если остаётся неподтверждённый обязательный сценарий.
