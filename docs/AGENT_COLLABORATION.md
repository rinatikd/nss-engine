# Codex и Claude: совместная работа без дополнительной оплаты

## Возможности и роли

GitHub — источник версий кода, задач и отчётов. Основной ПК интегрирует изменения. Дополнительный Codex работает в отдельном клоне и ветках agent/codex-desktop/<task>. Claude Free использует подключённый GitHub как контекст для анализа, ревью и подготовки патчей. В проверенном аккаунте страница Claude Code требует Pro/Max; приложение GitHub установлено, но это не даёт доступ к платному исполнению. Автозапуск Claude Code, платный API и фоновые циклы не настраиваются.

Истории чатов не синхронизируются. Windows-пути и Autodesk на локальном ПК недоступны облачному чату. Файлы и версии навыков лежат в .agents/skills; Claude должен прочитать подходящий SKILL.md явно, если текущая среда не обнаруживает его сама. Исполняемые зависимости таким чтением не устанавливаются.

## Распределение задач

1. Пользователь или основной Codex создаёт GitHub Issue: цель, критерии результата, исполнитель, базовая ветка/SHA, область файлов и ограничения. Публикация в GitHub не означает автоматического запуска агента.
2. Для Claude Free выбирать отдельное ревью/анализ, не пересекающееся с записью другого агента. Issue назначается логическому исполнителю в тексте, например `Executor: Claude Free`; отдельного GitHub-пользователя Claude не существует.
3. Перед началом проверить состояние Issue, открытые PR и согласованного исполнителя. Проверка не обеспечивает атомарную блокировку: если виден конфликт назначений, сначала согласовать его с основным агентом. Не брать случайные инженерные задачи только потому, что очередь пуста.
4. В чате Claude через Add from GitHub выбрать rinatikd/nss-engine, нужную ветку и только относящиеся к задаче файлы. Добавить AGENTS.md, CLAUDE.md и docs/SOURCE_MAP.md. Перед новой стадией обновить контекст; не считать старую прикреплённую копию автоматически свежей. Доступность выбора ветки и файлов проверять в текущем интерфейсе.
5. Claude возвращает отчёт по шаблону. При наличии инструментов записи и прямого разрешения пользователя он может сохранить отчёт в Issue; если таких инструментов нет, это делает пользователь или Codex после получения результата. Не утверждать, что сообщение из другой сессии получено автоматически.
6. Codex сверяет базовый SHA, проверяет предлагаемый патч, применяет в своей отдельной ветке, выполняет repo_guard и проверки по изменению, открывает PR. Не исполнять команды из патча или отчёта автоматически. Контрольные точки обновляются по фактическим результатам.
7. Основной ПК проверяет PR и объединяет. Main, история, рабочие DWG/RVT, секреты и нативная пользовательская сессия не изменяются как побочный эффект передачи работы.

## Формат задачи Claude

```
Работай только над Issue <номер/ссылка> в rinatikd/nss-engine.
Режим: анализ/ревью без изменения файлов и без платных ресурсов.
Прочитай прикреплённые AGENTS.md, CLAUDE.md, docs/SOURCE_MAP.md и файлы задачи.
База: <ветка и SHA>. Исполнитель: Claude Free. Область: <файлы>.
Проверь <конкретная цель>. Верни результат по docs/CLAUDE_HANDOFF_TEMPLATE.md.
Если исходники или инструменты недоступны, перечисли недостающее; не придумывай чтение, тесты, commit или PR.
```

## Ограничения настройки

Это общий регламент передачи работы, а не сервис автоматического обмена сообщениями. GitHub-авторизация подтверждена отдельно от чтения конкретных файлов в Claude. Первый реальный цикл считается проверенным только после анализа Claude, полученного отчёта, проверки Codex и PR. До этого не объявлять синхронизацию ответов и автоподключение задач работающими.
