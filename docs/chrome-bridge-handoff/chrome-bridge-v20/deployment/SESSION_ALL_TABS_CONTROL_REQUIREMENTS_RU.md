# PR #113 — единое разрешение управления вкладками на время подключения

Статус: **целевое требование пользователя, 15 ноября 2026; не объявлять готовым до E2E**.

## Пользовательская модель

**Подключить / Подключено / Отключить** — единственный пользовательский переключатель сессии Chrome Bridge. При явном нажатии **«Подключить»** расширение получает в рамках предусмотренного Chrome системного запроса host permissions доступ к обычным `http://` и `https://` вкладкам, включает фоновое соединение и устанавливает одну активную сессию управления вкладками. Для Claude, Gemini и других разрешённых сайтов не нужны отдельные кнопки **Grant Control**, 1/3/4-часовые таймеры или разрешения для каждой вкладки. Надпись **«Подключено»** допустима только после подтверждения активного соединения и действующих browser permissions.

Сессия не ограничена фиксированным количеством часов. Она продолжается, пока пользователь явно не нажмёт **«Отключить»**, либо пока соединение/разрешения не будут отозваны или перестанут быть действительными. Повторное подключение после полного отключения требует нового пользовательского действия и, при необходимости, системного разрешения Chrome. Не следует считать отсутствие отдельного origin-grant `control_status.origins=[]` доказательством отсутствия общей сессии, если применён one-click model.

## Границы разрешения и гарантии безопасности

Единое разрешение на браузерные вкладки **не означает** разрешения выполнять любые действия на страницах безусловно.

- Контроль распространяется только на вкладки обычного Интернета, разрешённые Chrome, не на `chrome://`, Chrome Web Store, страницы расширений, внутренние ресурсы, системные операции Windows или локальные секреты.
- Read-only инвентаризация всех подходящих веб-вкладок разрешена в рамках сессии. Изменяющие DOM действия допускаются только через проверенный командный интерфейс с проверкой origin/tab/context, сроков команды, авторизованных типов операций и защитой от навигационных гонок.
- Отправка сообщений ИИ требует проверенного адаптера и конкретного ID существующего диалога или проверенного однократного bootstrap первого сообщения. `requestId` уникален и хранится в durable journal до dispatch; UNKNOWN запрещено повторять автоматически.
- Покупки, оплаты, удаление аккаунтов, передача секретов, ввод паролей, OAuth/MFA, чувствительные или необратимые действия остаются отдельно запрещены/требуют индивидуальной проверки, несмотря на общую сессию.
- **«Отключить»** немедленно выключает дальнейший dispatch, прекращает транспорт и отзывает host permissions; требуется проверить результат отзыва. Ошибка остановки/revoke — fail closed с явной диагностикой, не «Подключено».
- Перезапуск/потеря соединения не должны незаметно восстанавливать полномочия, если сессия уже отключена; при восстановлении транспорта не допускать replay старых команд.
- Production и лабораторные порты, профили, расширения, state и токены остаются разделёнными.

## Приёмочные проверки

1. Один локальный клик `Подключить` → один системный запрос Chrome (когда нужен) → статус `Подключено` только при подтверждении сервера.
2. В одной сессии доступны две или более обычные веб-вкладки разных разрешённых origin без дополнительных кнопок Grant/таймеров; право host access и право на конкретную команду проверяются отдельно.
3. Отсутствие прежних per-origin grant не отключает one-click режим.
4. ИИ с проверенным адаптером способен выполнить подтверждённый send→ACK→reply в существующем диалоге и в новом диалоге при наличии bootstrap; UNKNOWN не повторяется.
5. Отдельные запрещённые страницы/команды остаются запрещёнными даже при общей сессии; выключение/отзыв/повторное подключение/restart/recovery проверяются E2E.
6. Проверить, что «Подключено» не сохраняется как ложный зелёный статус при исчезновении транспорта или отозванных host permissions.

**Не подменять доказательство Chrome UI/permissions, реального ACK и доставки только unit-тестами.**
