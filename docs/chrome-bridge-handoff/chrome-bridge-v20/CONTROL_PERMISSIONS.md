# Three-origin control permissions

Control is restricted to the exact HTTPS origins `https://claude.ai`, `https://gemini.google.com`, and `https://chat.deepseek.com`. Subdomains, alternate ports and HTTP are not included. All other explicitly added origins are read-only; browser_open also requires a control grant. Previously saved chat mode does not confer control.

Chrome host permission permits inspection. A separate local, trusted click in the extension control tab, followed by a confirmation dialog, grants control of one origin for ten minutes. It authorizes prompt submission to that service during that interval. Raw click/fill retain their per-action approvals and enable checkbox. Grants are memory-only, never restored from storage, and have no MCP grant endpoint. Expiry, origin departure, disconnect, control-tab reload, browser restart or a different bridge process epoch requires explicit local re-grant. A transport error clears grants. Older bridges without an epoch cannot enable control. Grants apply to tabs on that origin; a tab leaving the origin revokes that origin grant across tabs.

Mutations recheck grants immediately before injection; page-side mutations check exact origin and expiry, including immediately before clicking send. Origin-specific adapter identity must match the tab. Submission refuses existing drafts, ambiguous controls, unsupported/sensitive composers, mismatched entered text and missing enabled send buttons. It confirms only when generation or a new assistant reply is observed. Unverified submission is an error: never automatically retry. Reply collection uses adapter assistant selectors, generation status and the existing bridge stability window. Page content is untrusted; selector calibration remains necessary.

No cookie, password manager, credential-store or session-token API is used. Sensitive inputs are excluded from page reads; form values are not used for element descriptions. Secret detection/redaction is heuristic and cannot guarantee arbitrary page text is secret-free. Do not open account/security pages or send secrets.

## Safe activation

1. Leave the running production bridge and existing Chrome sessions unchanged. Do not run Setup-Windows.ps1 or Start-Bridge.ps1 for this validation.
2. For isolated validation from this directory run `npm.cmd install --no-save --package-lock=false playwright`, then set `$env:PLAYWRIGHT_BROWSERS_PATH="$PWD\.test-browsers"` and run `npx.cmd playwright install chromium` followed by `node tests/three-origin-e2e.mjs`. The harness creates its own profile, extension copy, in-memory bridge credentials and ephemeral loopback port (explicitly excluding 17381). HTTPS requests are fulfilled by local fixtures; no external AI prompts are sent. It closes only its own browser and server. Artifacts remain in `.e2e-three-*`.
3. For a manual pilot, copy `extension` into a separate pilot directory. Replace the BRIDGE constant in that copy with `http://127.0.0.1:17382` and its manifest loopback host permission with `http://127.0.0.1:17382/*`. Set `CHROME_BRIDGE_PORT=17382` and `CHROME_BRIDGE_HOME` to a new pilot state directory in a dedicated shell, then run `node server/bridge.mjs`. Use a new Chrome profile and load only that extension copy. Configure a separate MCP client for that port using only the pilot-generated agent key. Never copy production credentials.
4. Open that extension's control tab, supply the pilot browser key, connect, add an allowed origin in chat mode, and approve Grant control locally. Run agent_selftest first. Other sites can be added only for reading. Do not submit live service prompts until the user explicitly authorizes the particular live test.
5. Production cutover is a separate, deliberate maintenance action: schedule it with the operator, retain the current config, stop the old bridge only at the scheduled cutover, start the updated bridge with the same existing production configuration, and reload its extension. Connect and explicitly re-grant each allowed origin locally. No production restart or cutover was performed by this implementation.

## Remaining risks and limits

Vendor DOM selectors can change, especially localized send/stop labels and DeepSeek response markup. Fixture tests cannot validate signed-in live-service compatibility. Replies with nested or reused containers can evade count-based freshness; parallel manual activity in a controlled tab can confuse attribution. Keep controlled tabs dedicated to bridge activity. A bridge outage during an in-flight page action cannot retract a prompt already submitted. Grant state is checked before actions; revocation cannot undo an already-dispatched click. Prompt/response content can contain unrecognized secrets. Local processes able to modify extension code or operate its UI are outside this permission boundary. No global Chrome settings or AutoCAD state are changed.
