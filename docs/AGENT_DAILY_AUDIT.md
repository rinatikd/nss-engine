## Как выбирать задачи по возможностям

| Вид работы | Необходимое подтверждение | Текущий кандидат |
|---|---|---|
| Изменение кода, тесты, Git/PR | Локальный checkout, shell, рабочие проверки, изоляция ветки | Codex приложения; CLI основного ПК по подтверждённому назначению; Cursor после пробы |
| Независимое ревью diff | Чтение точной базы и diff, воспроизводимые основания | Grok; Gemini по проверенному пакету |
| Анализ вариантов/документации | Полный пакет задачи, честное обозначение пробелов | Gemini; другие после подтверждения канала |
| Нативная AutoCAD/Revit проверка | Нужный установленный хост и разрешённый способ проверки | Только фактически доступная среда; Revit на дополнительном ПК отсутствует, исходный DXF под ограничением импорта |
| Интеграция в main | Актуальные PR/CI, разрешённая роль интегратора | Основной ПК, без автоматического merge здесь |

Это кандидаты по инструментам, не рейтинги брендов. Цель — принятые полезные результаты на единицу времени/лимита, а не максимальное число одновременно открытых чатов. Установка handoff сама по себе не даёт доступа к репозиторию или автоматического обмена.

Дополнение за эту же дату: Qwen вошёл в работу через четырёхфайловый снимок, получил QWEN-01 и вернул три замечания. Начальная роль — граничные случаи/второе мнение на небольшом пакете, обязательно с локальной проверкой. Подробности в QWEN_REVIEW_01.md; исправление зарегистрировано SEC-01, но ещё не выполнено.

Для каждой завершённой задачи фиксировать исполнителя/режим, точную базу, реально прочитанные файлы, принятые существенные находки, дубли/ложные находки, доработки, время ответа/приёмки, проверки и результат интеграции. Сейчас данных недостаточно для численного сравнения. Лимиты проверены только у Codex: 70% окна пяти часов и 80% недели оставалось при этом запуске; это снимок, не резерв. Лимиты остальных неизвестны.

Ежедневный проход: сравнить с предыдущей датой, проверить новые результаты и блокировки, предложить максимум три действия, обновлять общий документ только при содержательном изменении. При отсутствии изменений — краткая локальная отметка, без нового коммита/повторного уведомления. Если приложение/ПК или включённый лимит недоступны, отметить пропуск и продолжить при следующем доступном запуске; расписание не гарантирует круглосуточное выполнение.
