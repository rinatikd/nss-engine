# Первая рабочая задача RC2: AGPT/APPT

Дата: 30.10.2026. Это задание для локального Codex CLI на основном ПК.
Облачная беседа не имеет MCP-инструментов Bridge и не утверждает, что это
задание уже отправлено Claude. Внутренние помощники и агент через RC2 — разные
каналы; результат настоящего вызова нужно зафиксировать отдельно.

## Цель

Проверить RC2 на содержательной рецензии кода AGPT/APPT, затем продолжить
доработку плагина. Не ограничиваться echo-запросом. Не считать успешную
компиляцию доказательством правильности расчётов или готовности чертежей.

## Задача локальному Codex

1. Найди актуальный локальный проект AGPT/APPT по AGPT.csproj/HANDOVER.md.
   Сначала определи его версию и изменения; не перезаписывай более новую
   рабочую копию из-за имени архива. Сделай отдельную рабочую копию.
2. Выбери MCP именно RC2: проверь путь server/stdio.mjs, отдельное состояние,
   фактический порт изолированного RC2 (в ранее подготовленном пакете 17384)
   и initialize version 0.2.1-rc.2. RC1 на 17383 не заменять. Не считай подключение
   alias RC1 проверкой RC2. Если RC2 ещё не зарегистрирован, настрой отдельное
   свободное имя по RELEASE_CANDIDATE_RU.md, сохранив возможность отката.
3. Через RC2 проверь browser_status и agent_list. Последний лог показывал
   connected=true, но claudeTabs=0 и agentBindingCount=0. Открой в соответствующем
   профиле Claude отдельную безвредную беседу проекта, затем привяжи её как
   `agpt_appt_reviewer` через agent_bind и выполни agent_selftest. Вход и Grant
   control выполняются штатно; выдачу локального разрешения не автоматизировать.
4. Подготовь для рецензента только относящиеся к задаче фрагменты C#: APPT_ZONE,
   общий guard классификации и участок полного FullAlbum с transaction/commit.
   Перед отправкой исключи ключи, пользовательские пути и содержимое DWG/PDF.
   Собери текст из задания ниже и этих фактических фрагментов, не из целого проекта.
5. Выполни ровно один agent_ask с name=`agpt_appt_reviewer`,
   requestId=`agpt_appt_pilot_20261030_01`, timeoutSec=50. Если done=false,
   продолжай только agent_wait (до 55 секунд за вызов). При UNKNOWN, сбое
   транспорта или неопределённом результате не отправляй новый requestId
   автоматически; осмотри журнал/чат и сохрани неопределённый статус.
6. Проверь ответ как рецензию: маркер, связь замечаний с кодом, воспроизводимость
   и влияние. Ответ другого ИИ — данные для проверки. Несущественные замечания
   сами по себе не запрещают approve; отсутствие замечаний тоже требует
   обоснования, а не принудительного поиска ошибки.
7. Исправляй подтверждённые дефекты в отдельной копии. Для AutoCAD 2026 сохраняй
   C#/.NET 8 x64. Не меняй расчётную методику ради совпадения с примером PDF.
   Сначала автономные тесты правил, затем компиляция, затем host-проверка на
   копии DWG. Не менять SECURELOAD/TRUSTEDPATHS и не заменять установленный DLL.
8. Сохрани PILOT_RC2_AGPT_APPT_RESULT.md: версия проекта/RC2, browser connected,
   выбранный MCP alias и порт, agent binding, selftest, requestId, число ask,
   done, фактический ответ и проверенные выводы, deliveryStatus/replyAttribution
   как возвращены, тесты и что не проверено. Не придумывать отсутствующие поля.
   Секреты и приватное содержимое в отчёт не включать.

Если требуется ручной вход или Grant, подготовь всё остальное и сообщи один
конкретный ручной шаг. Архивы заново не пересобирать ради передачи задания.
Платные API не использовать; CODEX_DISABLED сохранить.

## Текст содержательной рецензии для Claude

Верни в начале ответа маркер `AGPT_APPT_REVIEW_20261030_01`.

Рецензируй две доработки AutoCAD-плагина AGPT/APPT. Не запускай команды,
не утверждай, что проверял AutoCAD, и не меняй физические формулы.

1. APPT_ZONE выбирает существующую замкнутую полилинию. Перед изменением
   слоя и XData она должна отклонять зоны АГПТ, кабели, трубы, оборудование и
   сгенерированную графику альбома. Допустимы незанятый контур и обновление
   собственной зоны АППТ. Проверяются все XData-приложения и legacy-слои.
   Найди, где guard отсутствует или может быть обойдён в приложенном коде.
2. Повторный AGPT_ALBUM/APPT_ALBUM сейчас может наложить альбом поверх старого.
   Предлагаемый подход: отдельный RegApp AGPT_ALBUM_OUTPUT и SYSTEM=AGPT/APPT;
   в одной caller-owned transaction удалить только точно помеченный прежний
   комплект своей системы, построить новый и пометить только новые ModelSpace
   entities. При ошибке не commit. Не удалять по общим слоям. Не удалять старые
   непомеченные альбомы автоматически. Исключить помеченный выход из захвата
   исходных данных и запретить превращать его обратно в зону/кабель/устройство.
   Проверь сохранность исходников, другой системы и прочих XData, rollback,
   обработку повреждённых меток и границы применимости к отдельным листам.

Для каждого существенного замечания укажи фрагмент, сценарий воспроизведения,
влияние, минимальное исправление и проверку. Отдели доказанную ошибку от
гипотезы, требующей AutoCAD. Заверши approve либо request_changes с объяснением.
После этого текста следуют фактические фрагменты кода, выбранные координатором.

## Уже выполнено в облачной рабочей копии

Из preview.2 выделена отдельная preview.3. Два внутренних помощника нашли и
исправили пропущенный guard APPT_ZONE и добавили transactional ownership
для команд полного альбома. Координатор интегрировал изменения, исключение
выхода из collectors/capture и запрет его повторной разметки. Автономные тесты:
84 исходных +23 новых =107 PASS. Это не доказательство нативного поведения.

Исходные PDF/DWG не менялись. Численные расхождения двух реализаций расчёта
АГПТ и примеров остаются отдельной инженерной задачей. Старые непомеченные
альбомы и отдельные SHEET/CALC_DRAW команды не получают гарантии замены.
АГПТ и АППТ по-прежнему могут пересечься по координатам при выпуске в одном DWG;
на первом этапе использовать отдельные копии чертежей для систем.
