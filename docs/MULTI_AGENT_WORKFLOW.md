# Общая работа Codex, Cursor, Claude, Grok, Gemini, DeepSeek и Qwen

## Область и разрешение

Пользователь разрешил Grok (xAI), Gemini (Google), DeepSeek и Claude читать код/инструкции приватного NSS для совместной работы и намерен подключать другие проекты; отдельно поручил подключить Cursor и Qwen. Это не разрешение передавать секреты, локальные чертежи, чужие чаты или произвольные папки. Каждый следующий проект включается с явным названием, репозиторием/папкой и задачей. API, кредиты, подписки и публичные туннели без отдельного разрешения не используются. Репозитории сохраняются приватными.

## Один протокол для всех участников

- GitHub Issue: Project, Task, Executor, Base branch/SHA, Allowed files, Acceptance criteria, Dependencies, Status. Отдельные задачи могут выполняться параллельно в непересекающихся областях.
- Основной ПК назначает исполнителя и интегрирует результат. Проверка Issue — организационное правило, не атомарная блокировка; при двойном назначении требуется разрешить конфликт до записи.
- Перед назначением проверить канал чтения и доступный лимит. Участник читает AGENTS.md, docs/SOURCE_MAP.md, docs/PORTABLE_SKILLS.md и файлы конкретной задачи через подтверждённый канал. Если канала нет, назначать только анализ явно перечисленного, проверенного пакета контекста; отсутствующие файлы отмечать как непрочитанные. Навыки читаются явно, если клиент их не обнаруживает автоматически.
- Для исходников фиксируется конкретный SHA. Повторно проверить базу перед применением патча. Снимок чата не заменяет fetch и не обновляется автоматически.
- Ответ: задача, база, реально прочитанные файлы, выводы с основаниями, proposed diff, реально выполненные и только предлагаемые проверки, ограничения, следующий шаг. Общий формат полей — docs/CLAUDE_HANDOFF_TEMPLATE.md; имя файла историческое, формат применим ко всем.
- Чат без инструментов записи возвращает предложение; Codex получает результат, проверяет и применяет его в отдельной ветке agent/<executor>/<task>, затем создаёт PR. Нельзя заявлять несуществующие commit/push/PR или исполнение AutoCAD/Revit.
- Инструмент с правом записи использует только назначенную область и свою ветку. Main не обновляется этим участником напрямую. Принятие проекта остаётся за пользователем.

## Gemini: снимок вместо синхронизации

Google описывает импорт одного репозитория до 5000 файлов/100 MB в чат. Изменения после импорта не синхронизируются: повторить импорт нужной ветки и записать её SHA перед следующей задачей. Требуется Keep Activity; не менять настройку хранения активности автоматически ради подключения. Если функция недоступна, зафиксировать ограничение, не оформлять платную подписку.

## Grok и DeepSeek

У Grok не выдавать установленный коннектор за подтверждённое право создавать PR. Пользователь завершил подключение сам; последующая read-only проверка подтвердила чтение NSS, но не ширину разрешений. Для DeepSeek проверена текущая сессия обычного чата: API key и интеграции агентских harness не являются доказательством встроенного GitHub-доступа. Понадобится согласованный ограниченный пакет контекста; отсутствие ручного копирования пока не достигнуто. Не создавать обход через общий токен или публичный репозиторий.

### Назначение и завершение

Перед стартом координатор фиксирует Task ID, исполнителя, независимого проверяющего при необходимости, SHA, разрешённые файлы, критерии приёмки, ожидаемую проверку и время следующей контрольной точки. Основной ПК сохраняет право интеграции; Codex приложения готовит назначения/PR, пока основной ПК их не подтвердит. Фактический исполнитель подтверждает принятие задачи и базу до изменения файлов. Одновременно у исполнителя не более одной задачи в работе; дополнительные задачи ждут. Проверка очереди не является технической блокировкой Git.

Статусы: proposed → ready → sent → acknowledged/in_progress → reviewed → integrated. Отдельно: blocked_input, blocked_access, blocked_quota, waiting_user, rejected. Ready означает наличие входов и подходящего проверенного канала, а не факт отправки поручения. По истечении контрольной точки остановить конфликтующее назначение и проверить состояние; не забирать задачу молча и не перезаписывать ветку. Не назначать два изменения одних файлов одновременно. Разрешены независимые ревью одной неизменной базы.

Для выбора исполнителя сначала применить обязательные условия: разрешённые данные, подтверждённый канал, требуемый хост/инструменты и доступный лимит. Неизвестный лимит отмечать как неизвестный; интерфейс отсутствующего API не имитировать. Затем учитывать принятые результаты на похожих задачах, время и объём исправлений проверяющим. До накопления результатов назначать ограниченную пробную задачу; постоянные роли по бренду модели не вводить. Выполнение полезной задачи важнее загрузки всех участников.

Для результата записать: принятые существенные находки, отклонённые/дублирующие находки, пройденные проверки, время получения и доработки, статус принятия, известную стоимость либо «неизвестна; платные ресурсы не включались». Нельзя вычислять проценты качества без достаточного числа сопоставимых задач. Для важной логики нужен отдельный проверяющий; автор не является единственным основанием принятия собственного изменения. Для простой документации достаточно проверки diff и ссылок координатором.

Пакет контекста содержит репозиторий, ветку/SHA, список разрешённых файлов с хешами, цель и критерии результата. Хранить одну версию пакета для сравниваемой задачи. Если SHA изменился, пересмотреть применимость ответа перед патчем. Непрочитанные файлы и непроведённые хост-проверки указывать явно. Новые общие правила должны быть интегрированы в main и получены другими клонами: открытый PR не распространяется автоматически.

### Ежедневная оценка

Один раз за календарные сутки Asia/Qyzylorda проверять очередь, новые результаты/PR, ожидания, подтверждения возможностей и доступные лимиты. Использовать новые свидетельства, а не повторять все логины/пробы. Записывать дату, базу и изменения со вчерашнего дня; предлагать не более трёх полезных действий. Если изменений нет, сохранить краткую локальную отметку и не переписывать Git-документы/не уведомлять повторно. Нет доступа к другому ПК/чату — указать «не проверено», не читать посторонние беседы. Ежедневный анализ не разрешает самостоятельно отправлять внешним агентам сообщения или включать платные каналы.

Автоматический диспетчер пока не реализуется. Выбор кандидата основывать на доступе к данным и инструментам, свободных лимитах, характере задачи и измеренных результатах. Не назначать модели постоянную специализацию по бренду. Для сравнения давать независимый одинаковый пакет/базу, измерять правильность, пропуски/ложные замечания, число правок, время, стоимость и принятие результата. Нативные CAD/BIM-проверки поручать только среде с доступным Autodesk.

Пока нет общей истории измерений, назначение делает основной агент/пользователь. При исчерпанном лимите участника не повторять запросы циклически; сохранять следующий шаг. Автоматизация браузера не считается официальным фоновым API или гарантированно работающим каналом обмена.
