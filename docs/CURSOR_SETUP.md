## Подключение на выбранном ПК

1. Проверить фактическую установку и войти в существующий аккаунт Cursor. Не оформлять платный план, не включать usage-based spend, внешние API или Cloud Agents как побочный шаг. Доступность включённого использования проверить в текущем аккаунте.
2. Создать отдельный клон rinatikd/nss-engine рядом с занятыми рабочими копиями. Не открывать Cursor для параллельной записи в каталог, где уже работает Codex CLI или другой агент. Не клонировать поверх непустой папки.
3. Проверить origin, git status и fetch. Создать agent/cursor/<task> от актуальной origin/main после получения конкретной задачи. Не брать автоматически все задачи проекта и не менять ветки основной копии.
4. Открыть этот клон в Cursor через Open Folder. Проверить обнаружение AGENTS.md и названий навыков. До запуска модели проверить настройки обработки кода и согласованный объём передаваемого проекта; секреты, инженерные входы вне репозитория и чужие папки не добавлять.
5. Первой read-only проверкой попросить агента назвать текущую папку, ветку, SHA и кратко пересказать правила из реально прочитанных AGENTS.md/README. Не выполнять команды изменения AutoCAD/Revit.
6. После этой проверки назначить отдельную ограниченную задачу. Перед коммитом запускать tools/repo_guard.py --staged; перед push — tools/repo_guard.py --tree HEAD и проверки по изменению. Результат — отдельный PR. Main интегрирует основной ПК.

Для локальной работы Git использует авторизацию выбранного ПК; подключение GitHub к облачной стороне Cursor не является обязательным условием обычного clone/push через локальный Git. Если выбран облачный режим или дополнительная интеграция, сначала проверить её отдельные права, стоимость и условия. Репозиторий не переносить с GitHub в другой хостинг ради настройки.
