## Что известно и что пока является гипотезой

У конкретной веб-сессии пока нет измеренных результатов: нельзя честно назвать её сильнее других в коде, математике или инженерии. Возможные полезные роли для проверки: независимое ревью небольших Python-функций, поиск граничных случаев, предложение тестовых сценариев и проверка табличной согласованности на ограниченном пакете. Назначать их как пробы с критериями, а не как постоянную специализацию.

Объективные ограничения текущего подключения: GitHub-доступ, локальные файлы, shell и PR не проверены; у веб-чата нет подтверждённой связи с AutoCAD/Revit. Данные, переданные снимком, не обновляются сами. Нормативные и CAD-выводы требуют первичных источников и проверки подходящим хостом независимо от модели. На дополнительном ПК мало свободного диска; новый локальный runtime без необходимости не устанавливать.

Отдельный продукт Qwen Code документирует локальные файловые инструменты, CLI/IDE и режимы разрешений. Это возможный будущий способ уменьшить ручную передачу пакетов; документация Qwen Code не доказывает эти возможности у chat.qwen.ai или доступный бесплатный лимит аккаунта. В этом этапе Qwen Code не установлен, API/OAuth-токены не созданы и платные ресурсы не включены.

## Первая полезная проба QWEN-01

После входа сначала определить фактические инструменты веб-чата. Не просить модель искать приватный репозиторий публичным поиском вместо доступа. При отсутствии подтверждённого GitHub-чтения использовать ограниченный пакет: AGENTS.md, tools/repo_guard.py и текст задачи из этой секции. Перед передачей записать полный SHA и SHA256 каждого файла. Не добавлять Git credentials, реальные секреты, установленные SDK или пользовательские входы.

Задача: независимое read-only ревью tools/repo_guard.py. Найти не более трёх воспроизводимых дефектов или существенных пробелов, относящихся к проверкам запрещённых артефактов/утечек и достоверности результата. Для каждого: место в файле, минимальный синтетический пример, ожидаемое и фактическое поведение, влияние, минимальная предлагаемая правка/тест. Не использовать настоящие ключи. Если исполнять Python негде, прямо обозначить сценарии как предложенные, а не выполненные. Не предлагать загрузить реальные секреты или ослабить ограничения ради зелёной проверки. Не придумывать замечания для заполнения трёх пунктов. Ответ по CLAUDE_HANDOFF_TEMPLATE.md, изменение файлов и Git не поручается.

Проверяющий: Codex приложения воспроизводит каждую существенную находку на синтетических входах отдельно от рабочих файлов и принимает/отклоняет с основанием. Сравнивать долю принятых находок, дубли, время и объём доработки; одной пробы недостаточно для рейтинга. После успешного ревью следующая задача — конкретная полезная область с теми же требованиями к доказательствам.
